# Book Video Agent Guide

This repository is an open-source, natural-language workflow for producing short book videos. Keep reusable code, templates, owned assets, and distilled methods in Git. Keep credentials, private book data, downloaded reference videos, generated episode work, and account data local.

## Startup Checklist

For the first user message in this repository, including a simple greeting such as "你好", run the startup checklist before normal task work unless `.book-automation-state.json` already exists and the user is asking an unrelated repository-maintenance question.

1. Resolve the current repository root with `git rev-parse --show-toplevel`; never hard-code a previous clone path. Check Codex capabilities first: the HyperFrames plugin/Skill and built-in bitmap image generation are capabilities, not user-installed project dependencies. Use them directly when available; do not ask the user to install a separate image model or HyperFrames Skill. Built-in image generation is only the fallback for the rare background beat that no Pexels photo can carry (see Visual And Audio Rules); the Pexels API and its fetch scripts are the default path for background stills.
2. Check local runtime prerequisites in one pass by running `node scripts/init.mjs` from the resolved repository root. Do not replace this with an ad-hoc `command -v` plus parsed `--version` output: FFmpeg and FFprobe commonly write version banners to stderr, so a blank stdout is not a missing-command signal. Trust the command exit status and the JSON check result. If Node.js 22+, `npx`, FFmpeg/FFprobe, or `whisper-cli` are missing, report the complete list and ask for one confirmation before installing them. After confirmation, the Agent may install them with the available platform package manager; never install or change system packages silently. The repository does not auto-install these through a project script.
3. HyperFrames runs through `npx hyperframes@0.7.33`, so the first check or render may need npm registry access even when the HyperFrames Skill is available. If `npx` reports `ENETUNREACH`, `EACCES`, `ENOTFOUND`, `ENOTCACHED`, registry access blocked, or a system network policy failure, classify it as an environment/network issue and immediately retry the same check/render with the execution tool's network-capable escalation. Do not ask the user for a second confirmation or ask them to repeat the workflow. Only report the blocker if the escalation itself is denied or fails. Try the local npm cache with `npx --offline` only as a quick fallback; it cannot replace network access when the package is not cached.
4. Check the model at `<repo-root>/assets/models/whisper/ggml-base.bin` using file existence and size, not `ls` output alone; a valid file is at least 100 MB. If missing, ask to download it as part of the confirmed setup, then run `node scripts/download-whisper-model.mjs`. If the download fails, first look for an enabled computer proxy or proxy environment variable; use it for a retry with `--proxy`, asking the user to enable their proxy when none is active. Do not change system network settings silently. If that fails, give the user the browser URL `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-base.bin`, then install the user-provided file with `node scripts/download-whisper-model.mjs --from "<local-path>"`.
5. Ensure the official Tencent WeChat Reading Skill is installed and enabled through the agent's skill installer when absent; do not ask whether to enable it and do not vendor its source into this repository.
6. If the initialization result reports `wereadApiKey: true` or `weread: enabled`, treat WeChat Reading as configured and never ask for the key again. Only when the result reports it is missing, ask whether to configure the integration. After confirmation, open [微信读书 Skills 官网](https://weread.qq.com/r/weread-skills) with the browser/computer tool and explicitly tell the user: “请在页面获取 API Key，完成后回到本对话把 Key 发给 Agent。” After the user sends it, store it in local `.env` with mode `0600`; never echo or log the key, and never accept it as a command argument. If the user declines key configuration, continue with public research.
7. Run `scripts/init.mjs` after the dependency and Skill checks. It creates local state and the private pipeline file without asking a second WeChat Reading enablement question.

After a body voiceover is supplied, run `node scripts/create-body-timings.mjs "<book>" [script-version]`. When the version is omitted, the Agent resolves it from `brief.json` or the unique version in `script-body.csv`. It creates `body-timings.json` from speech pauses and keeps Whisper output only as Agent review context because ASR may contain wrong characters. If pause segmentation is insufficient, estimate timings from speech duration and script hints, mark `alignment.requiresAgentReview`, and continue. Use `--skip-leading` to select how many spoken lead-in segments precede the first script row.

Initialization must be idempotent. It must not reinstall a verified skill, overwrite a valid key, reset user choices, or duplicate CSV columns.

## Book Selection

- If the user names a book, use it after verifying title and author.
- If `data/book-pipeline.csv` is missing, header-only, or has no usable candidates, ask one question covering preferred genre, emotional theme, or audience.
- With a preference, search according to it. Without a preference, search literary/philosophical books with strong emotional resonance for young adults.
- After every candidate search, write the complete result set to the local ignored `data/book-pipeline.csv` before recommending. Use `node scripts/record-book-candidates.mjs <candidates.json>` so fields are normalized and duplicate results are merged; never only present search results in chat.
- Recommend five candidates from the recorded rows and mark one top recommendation. Wait for book selection before drafting.
- When the WeChat Reading Skill is installed and configured, use it flexibly as the preferred research source for book metadata, popular highlights, and public reviews during book discovery and script preparation. Treat its results as research signals, not copy to reproduce. Public sources and user-provided material remain valid supplements or fallbacks when the Skill has no useful result.

## Book Metadata

Use `display_title` for folder names, visible labels, and scripts. Keep the exact source result in `source_title`; never overwrite it during normalization. Keep `source_book_id` and `source_channel` for provenance. Ambiguous editions, guides, summaries, or author mismatches require review.

## Production Gates

1. After book selection, create a provisional `script-body.csv` and run `node scripts/validate-script.mjs "<book>"` before showing any draft to the user. If it fails, shorten and revise internally, then validate again; never send an over-limit draft for approval. Only after it passes, send one active script for approval. The response must include the complete copy-ready voiceover in one Markdown fenced code block. The first line must be the display title in the form `《书名》`, followed immediately by every line to be read aloud. Do not put CSV headers, order numbers, author labels, timing data, or explanations inside the block. A `script-body.csv` attachment or file path is supplementary and must never be the only presentation; the whole block must be directly copyable into Jianying for audio generation.
The copy-ready script targets the **long** band by default: 4-5 minutes, about 1100-1450 Chinese characters in the body. Hard limits are at most 200 body rows and about 10000 Chinese characters. The `short` band (18-20 total lines including the title, hard limit 22, 180-300 characters, about 1 minute) is an exception used only when the user explicitly asks for a short version; pass `--short` to `validate-script.mjs` for it, and never present a short draft as if it were the default. Both bands, the narration rate used to convert characters to seconds, and the 3.0s intro offset live in `scripts/lib/script-policy.mjs` (`SCRIPT_LENGTH_PRESETS` / `DEFAULT_SCRIPT_PRESET` / `NARRATION_RATE_CPS`); never restate the numbers by hand. The rate is measured, not assumed: 4.69 characters/second median across the 99 delivered episodes in `episodes/待上传/`, computed from each final's ffprobe duration minus the 3.0s intro, divided by that episode's body character count (p10-p90 4.42-5.05). 98 of those 99 sit at 797+ characters, median 1220, so the house style is long and a ~200-character draft is a drafting miss, not a valid default. A draft is sent for approval only when `validate-script.mjs` reports a `long` band; a `short` result is a note the Agent must resolve, either by expanding to the long band or by confirming with the user that this episode is a short one. This gate belongs to the drafting stage; audio timing and final rendering checks are secondary safeguards, not the first validation point.
2. Only after script approval, source the background stills from Pexels (see Visual And Audio Rules): search portrait photos per narrative beat with `scripts/fetch-pexels-images.mjs` (the body set lands in `episodes/<书名>/images-body/`, the hook set in `images-hook/`, selected with `IMAGES_SUBDIR`; `scripts/lib/episode_paths.py` is the single resolver for the `images-body` / legacy `images` name and every consumer imports it, so never re-add a hard-coded `"images"`), record every adopted pick with `PROVENANCE_OUT=<episode>/pexels-fetch-log.jsonl` so the photo id and photographer are written down by the fetch itself rather than remembered, lock the adopted picks by photo id in `data/<书名>_pexels_ids.json` (`segment: "hook" | "body"` disambiguates the two sets, which share `atmosphere-N` basenames), then grade the whole set once per segment (`IMAGES_SUBDIR=… scripts/grade-atmosphere-images.py` followed by `IMAGES_SUBDIR=… scripts/fix-bright-regions.py`; re-run with `--restore` first, because grading is in-place and stacks). Map every row of the segment script to a layer in `episodes/<书名>/scene-map.json` (`{"index","name","order_start","order_end","theme"}`, the static `result-bridge` is layer 0, contiguous coverage of rows 1..max_order), and record each adopted photo's id, photographer, URL, crop and grade in `prompts.csv` with `filename` carrying the real directory prefix (`images-body/…`, `images-hook/…`) so the gate can match a hook row and a body row with the same basename. Declare `"image_pipeline": "pexels-1024"` in `brief.json`, then run `python3 scripts/check-image-provenance.py "<书名>"`; that gate is red when a shipped image has no Pexels provenance, when a layer points at a missing file, when a still is smaller than the 720x960 canvas (the render would upscale it), or when grading was skipped. The gate is red in the **other** direction too — a photo id the manifest locks but no file on disk lands. That check only warned until 2026-10-03: renaming 《海鸥》's `images-hook/atmosphere-16.png` out of the way still printed `背景图溯源门禁：全部通过`, and a hook segment is two beats, so losing one is losing half the hook. A **third** direction is the one that actually shipped a wrong frame: the manifest wants Pexels #A, the disk holds Pexels #B under the same basename, the file exists, is the right size and is graded — so neither direction can see it, because both only ask "is there a file for this id". `fetch-pexels-by-id.py` used to skip any name that already existed; that skip is the entry point. 《偏跟山过不去》 2026-10-03 re-locked a hook beat, the fetcher printed `完成 1/1` while writing nothing, the re-render faithfully put the *old* photograph back on screen, and eight gates stayed green. Identity is now carried by a written marker rather than inferred: every successful fetch records into `images-hook/_provenance.json` / `images-body/_provenance.json` (per filename: `photo_id`, the `_raw/` bytes' sha256, the shipped file's sha256 at fetch time, the source URL it actually pulled), `check-image-provenance.py` reds a marker whose id differs from the manifest («换图没真的落盘»), a name missing from an existing marker, a missing `_raw/`, and `_raw` bytes that drifted under the marker — the last one matters because `grade-atmosphere-images.py --restore` copies `_raw/` straight back over the shipped still, so a stale `_raw` silently resurrects the discarded photo. `lock-pexels-candidates.py` writes `replaces_photo_id` when a re-lock changes the photo, so the fetcher prints 覆盖重取 instead of 跳过. The fetcher no longer treats "file exists" as success at all: without a marker it says it cannot prove the file is that photo, and with a mismatching marker it re-fetches. `scripts/verify-pexels-fetch.py` closes the final gap by re-downloading each still from the recorded `image_url` (never a guessed extension), cropping it with the same `scripts/lib/pexels_crop.py` the fetcher imports, and comparing it to `_raw/` — it is an **opt-in** delivery gate (`check-episode-delivery.py --verify-photos`) because it needs the network, and it reports 未能证明 rather than 不符 when it cannot get the rendition it asked for. **The rendition is now part of the record, not an assumption:** the CDN's `w=1600` and `w=1280` are two *renderings of the same master*, and `crop_3x4()` LANCZOS-resizes each of them to 1024x1365, so their pixels differ — `fetch-pexels-by-id.py`'s width ladder lands on 1280 whenever curl 18 (transfer closed) breaks a 1600 request, and that was invisible to the verifier, which always asked 1600. 《猎人笔记》 2026-10-06 `atmosphere-5` (Pexels #32176786) was fetched at 1280, replayed at 1600, and reddened as 不符 (mean 5.0, peak 71) while the identical replay at 1280 measured **mean 0.000 / peak 0 / overshoot 0.000%** (and at 1024: 10.80 / 136). A false red of that shape sends a person to replace a photograph that has nothing wrong with it, and the cost is a whole body set re-fetched, re-graded, re-rendered. So `certify()` writes `source_width` — the **actual pixel width of the source that landed**, not the rung requested — into `_provenance.json`, and `verify-pexels-fetch.py`'s `replay_width()` resolves the rung in three steps (marker's `source_width` → the `_original/<name>.png` width for pre-2026-10-06 markers → default 1600), refuses to compare at all when the resolved width is below `TARGET_W` (a crop from there is an upscale, so it proves nothing), and reports 未能证明 — never 不符 — when the CDN returns a width other than the one recorded. `scripts/tests/test-replay-width.py` runs the real `main()` against a stubbed CDN and asserts all three directions (same rung + same photo green, same rung + different photo red 「不符」, same photo + different rendition red 「未能证明」 and its output must not contain 不符), plus that the rendition-vs-rung gap itself is >3× `MEAN_TOL` so the test cannot go vacuous; `npm run check` runs it and statically guards that the test still names `replay_width`, `source_width`, `fetch_bytes` and both script filenames. Do not substitute a perceptual hash for the marker chain: measured on this very set, the *same* photograph raw-vs-graded scores dHash distance up to 31 while two *different* photographs score as low as 12, so once grading is in-place a hash cannot prove "this file is that photo" — the checkable chain is manifest id → `_provenance.json` → `_raw` sha256 → graded still → delivered frame (`scripts/check-hook-frame-match.py`), and `npm run check` statically guards that the marker is written *and* read, that one `crop_3x4()` serves both fetcher and verifier, and that the exists-skip still goes through `certified_existing()`. A marker is demanded only in an image directory that already carries one, so the delivered legacy episodes stay out of the blast radius instead of turning this into a hundred-episode dig. Cross-*episode* duplicates used to stay outside every gate — the same photograph could sit in one episode's body and another's hook and nothing in the repo could see it, because every check only ever opened one episode. That stopped being acceptable the moment the 113-episode hook backfill made it the normal case (two hook beats × a hundred-plus episodes drawing on one Pexels library): 11 hook stills across 10 episodes replayed a photograph the viewer had already seen in another episode's body, and all eight gates stayed green. The judgement now has a single source, `scripts/lib/pexels_index.py` (`photo_id → [(episode, segment, filename)]`, built once per process from every `episodes/*/prompts.csv` and every `data/*_pexels_ids.json`), and **three** consumers share it: `scripts/pexels_candidates.py --exclude-used` drops already-shipped ids at search time so a batch never has to re-review them, `scripts/lock-pexels-candidates.py` and `scripts/lock-pexels-selection.py` refuse a hook pick the repo has already shown (a deliberate callback needs `--allow-used-elsewhere` plus a `reason` in the picks file), and `check-image-provenance.py` reds a locked hook still that any other episode has shipped — naming the offending layers. **A body pick is checked in the other direction only: `lock-pexels-candidates.py` refuses a photograph any other episode has already shipped *as a hook* (`if x[1] == "hook"`), because the red line lives on the hook side and the intrusion comes from the body — 《猎人笔记》 2026-10-06 locked Pexels #13438765 into body `atmosphere-4`, twelve gates green for that episode, and the `npm run check` sweep reddened 《女儿红》, a film delivered on 10-03 whose hook had already shown that photograph. Body-to-body repeats stay tolerated (#34938048 sits in ten episodes' bodies) — blacklisting them empties the pool batch after batch and a passing overfield carries no "where is this" expectation.** `npm run check` statically guards that all three are still wired to the lib and that `foreign_uses()` is defined nowhere else. **`--exclude-used` cannot see a photograph a human rejected**, because a rejected pick was never shipped — so the same defect photo came back every single batch: the six frames of one 大理稻田 family snapshot (Pexels `alt` = the garbage tags "animals, Beautiful scenery, beautiful woman", so *any* atmosphere query recalls them) surfaced in 15 candidate batches during the fourth hook batch on 2026-10-03, and a Chinese village corridor with a row of readable notice boards (#39854273) in 18. Manual rejection that lives only in a chat session is not pipeline state. `data/pexels-rejected.json` is now that state, read through one entry point, `scripts/lib/pexels_reject.py`: `pexels_candidates.py` drops those ids by default (`--ignore-rejected` only to re-audit a rejection), and **both** lock scripts refuse to lock one — the exemption is a photo already present in that episode's own manifest, because re-locking a segment must not be bricked by a list that grew afterwards, and withdrawing a shipped still is a re-pick + re-render, never a list edit. Write entries with `scripts/reject-pexels-photo.py`, which refuses a reason that is not one of the three *globally* disqualifying defects (a face, readable signage, a staged lifestyle/prop shot) and refuses an id that already shipped. Do **not** add a photograph that is merely wrong for one episode: a 江南 white-walled courtyard is a defect for a 西北 village story and a correct still for another, and blacklisting per-episode mismatches just shrinks the pool batch after batch. `npm run check` guards the four wirings plus that every recorded reason is one of those three classes and no recorded id has ever shipped. A related failure the same batch exposed: a transient proxy `503 Tunnel connection failed` used to end a query for good, so three of twenty hook beats came back with 3 candidates instead of 6, a reviewer then wrote 「无可用，需重检索」, and a whole episode got re-picked because of a network hiccup — `pexels_candidates.py` now retries those (4 s/8 s backoff) and exits **3** naming the queries that never completed, which means *the pool is narrower than designed*, not *Pexels has no such photograph*. A hook-only re-lock is merge-preserving in both the manifest writer and `write-prompts-csv.py`: 14–23 body provenance rows must survive it (《秋园》 2026-10-02 lost them to an overwrite write). Note that the index is only as complete as the manifests and CSVs it reads — an episode directory moved out of `episodes/` leaves its `data/*_pexels_ids.json` behind and keeps contributing to the dedup set, which is what you want; a delivered episode with *neither* file is invisible, so never delete provenance to tidy up. The gate measures size, luminance and traceability — it cannot see an anachronism, so before locking picks, open every shipped still at full size (never a thumbnail contact sheet) and look for objects that could not exist in the story's period or place: a lit green EXIT sign over a staircase, a row of snow-covered cars on the street where a character walks out without shoes, signage, antennas, plastic chairs. Both defects were shipped and caught only on review in 《涅朵奇卡：一个女人的一生》 2026-10-01; a 13 s EXIT sign and a 48 s car-lined street pass every quantitative gate unchanged, so replace the pick, re-grade the whole set, and update the manifest, `prompts.csv` and the layer `theme` together. When the anachronism is only *at one edge* of a photograph whose light, colour temperature and emptiness are right, do not discard the pick — give the manifest entry a `"crop_box": [x0,y0,x1,y1]` (fractional window applied to the source before the 3:4 centre crop), and `scripts/fetch-pexels-by-id.py` will cut the object out of frame while `write-prompts-csv.py` prints the real crop method instead of claiming a centre crop. 《达洛维夫人》 2026-10-02: 13 of 18 shipped stills carried a defect (a bus shelter, a delivery scooter, Japanese shop signage, double-yellow lines, two tourists in modern dress beside an arcade), and the one image that could not be re-searched — every Bond Street candidate had the same problem — was kept and fixed with `crop_box [0,0,0.8,1]`, which is why re-searching a beat that has no clean photograph left is the wrong move. A third class is not modern at all and no keyword filter can catch it: a *staged prop still life* whose every object is old but belongs to another culture, or a photograph that illustrates the spoken line literally instead of carrying its mood. 《异乡人》 2026-10-02 shipped the 守灵 beat as a horned cattle skull behind an elephant-relief silver cigar ashtray — nothing anachronistic, its Pexels `alt` named no defect, and it passed the size/luminance/traceability gate unchanged — but it is not a 1940s Algiers retirement-home room, and it draws 「他想点一根烟」 as a picture-book ashtray. Reject that pick for an empty room with one chair; judge it on place and on atmosphere, not only on "could this object exist".
3. When body voiceover is supplied, process it with the `story` preset, use ASR only for timing, and keep `script-body.csv` as subtitle truth. Build the caption axis from ASR **token timestamps**, in this order: `node scripts/asr-segmented.mjs "<book>" episodes/<book>/audio/body-voiceover-story.mp3` → `python3 scripts/asr-to-simplified.py episodes/<book>/audio/asr/body.json` → `node scripts/create-body-timings-precise.mjs "<book>"` → `python3 scripts/snap-body-timings-vad.py "<book>" --apply` → `python3 scripts/audit-caption-axis.py "<book>" --apply`. A pause-tiling axis (`create-body-timings.mjs`) is a degradation, not the default: it tiles captions end-to-start so the shape looks perfect (last `end` ÷ duration ≈ 0.99, zero gaps) while every row is attached to the wrong sentence — 《茶馆》 2026-09-28 shipped 14–16 s late at rows 38-45 and every gate stayed green. The audit pass removes the five residual defects that a token axis still has (late start, mid-speech blank, unreadable window, tail dragged into a pause, and a tail so thin it dilutes the row's own voiced share below the gate's 45 % — rule C2, which trims only to the row's last audible burst) and leaves caption *starts* alone unless rules D/E fire, because at −50 dB a token onset and an energy onset differ by 0.03 s median while a threshold-driven head move swallows weak initial consonants. Those head rules must run **twice** — once before the C/C2 tail pass and once again after it, immediately before the monotonic guard — because rule D decides whether a row can move onto its own onset by looking at the *previous row's `end` at that moment*, and the previous row's tail is not reclaimed until C/C2 run, so a single head pass always loses the silence that C2 has just freed. Rule D's witness is the −50 dB silence runs, which answer only "is there a pause", so a sentence read without an internal pause merges into **one continuous voiced block** and `onset_of` hands D the onset of the *block*, not of the row's first word; when that block onset sits at or before the previous row's `end`, `on > prev_end + 0.10` is never true, and a head a full 0.77 s late is invisible both to the fixer and to the audit's own residual count (《李尔王》 2026-10-04 rows 15/27 「她说，父王，」: the last −50 dB silence ends at 28.56 while the block runs to 34.4, row 14 ends at 28.60, so only gate 7's per-row coverage saw it). Rule **D2** (`late-start-own`) is the fallback: it re-reads the witness the delivery gate itself uses (`lib/caption_speech.audible_windows` → `own_spans`) and moves a head **earlier only**, onto that row's own audible onset, and only when the previous row has released the space and the window stays above `min_window` — moving a head later stays forbidden because it swallows weak initial consonants. Control-measured: on 李尔王 D2 fires on exactly those two rows and drives gate 7 to 0 reds, while dry-running the audit over eight delivered axes (异乡人/三体1·地球往事/偏跟山过不去/秋园/茶馆/追忆似水年华/等待戈多/人间失格) reports **zero** `late-start-own` changes, so the rule touches only axes already fighting gate 7; `npm run check` statically guards that `fix_heads` still consults `own_spans` under that note kind. Measured on 《达洛维夫人》 2026-10-02 with the same snap output as input: one pass leaves `行首落后 2 行` residual (row 41 parks 0.39 s, row 88 0.46 s after their own onsets) and gate 6 exits non-zero; the second pass drives the residual to 0 with gate 7 unchanged at 0 reds. Do not "fix" the thin-tail reds by adding a third trimmer to the coverage pass — `snap-body-timings-vad.py` deliberately holds its 0.60 s lead-out and its 0.90 s readability floor, and the audit's rule C2 owns density with the audit's own 0.55 s read floor; two hands trimming tails to two different floors is the divergence that re-opens row after row.
   The coverage pass goes **before** the audit pass, never after: `snap-body-timings-vad.py` forces each caption window to cover the window in which its own words are audible and holds a row up to 0.60 s past them, while the audit's rule C trims exactly that kind of tail hold — audit-first would be re-widened, snap-first leaves the audit free to trim tails and fill blanks without uncovering a row (verified on 《恶女的告白》 2026-09-28: after `audit-caption-axis.py --apply` changed 31 rows, `check-caption-speech-align.py` still reported 0 reds).
   The coverage pass exists because a token axis is only as good as Whisper's predicted timestamps: without DTW every token `t_dtw` is `-1` and in-window times are linearly squashed, so a row can be attributed to the right sentence and still be 1–3 s off it (《恶女的告白》 2026-09-28: |Δstart| median 0.12 s but max 1.33 s on the corrected axis, 3.04 s on the shipped one). `scripts/snap-body-timings-vad.py` derives, per row, the window in which *that row's own characters* are audible — ASR character order to pin the row to tokens, waveform energy bursts to pin the pinned head/tail to something you can hear — then makes each caption window cover it, yields to the next row, holds at most 0.60 s past its own speech, and never drops below the 0.90 s readable window. Row heads may only move into a real silence gap; the tail of the previous row's lead-out is the first thing reclaimed when a row needs more time. `scripts/lib/caption_speech.py` is the single source of that "audible window" so the fixer and the gate cannot diverge; `check-caption-speech-align.py` judges the shipped `caption-track.json`, not `body-timings.json`, because the renderer still stretches short rows by characters ÷ speaking rate. That stretch must stay **capped by the density of the window it creates**: `render_scene_map_template_fallback.py` measures the energy bursts inside the row's axis window and refuses any extension that pushes the *whole resulting window* below `CAP_VOICED_MIN` (0.50, five points above the gate's 0.45), because the 0.90 s readability floor plus a 0.3 s single-word row is 33 % voiced and no axis can be walked out of that (《恶意》 2026-10-01 row 1 「恶意」: axis 0.36–0.95 scored 51 %, the hard floor dragged it to 0.36–1.26 and gate 7 went red — `CAP_MIN_KEEP=0.6` was the old per-episode hand patch, the cap is now automatic). The cap must **not** be phrased as "yield when the tail genuinely carries speech": the burst right after a row's end is usually the *next* row's first syllable, so that test passes on a tail that buys this row nothing. 《达洛维夫人》 2026-10-02 row 130 「她想，」: axis 235.36–235.91 scored 51 %, the next row opened at 236.20, the old test saw 0.06 s of energy in the 0.35 s it wanted to borrow and stretched the row to 236.15 — 0.79 s window, 0.28 s of its own speech, 35 %, gate 7 red again *after* the axis itself had gone green. The same window also parks the next row's first character under the previous caption, which is the mirrored defect the coverage pass forbids. "Valid" means token-derived: the shipped row must sit on the sentence that is actually being spoken, not merely fill the timeline. Three independent witnesses exist — ASR token timestamps (text↔time), `silencedetect` energy boundaries (blank↔speech), and the per-row audible window built from both (`scripts/lib/caption_speech.py`: ASR character order pins a row to tokens, waveform energy bursts pin those token ends to something you can hear) — and **all three** are delivery gates (`create-body-timings-precise.mjs --verify`, `audit-caption-axis.py --json`, `check-caption-speech-align.py --track`); shape-only checks (last-`end` coverage ratio, zero inter-row gaps, RMS envelope, loudness, the caption boundary sweep) are blind to row attribution and stayed green on an axis that was 16 s off. Digit-by-digit, **not** cardinal: BPE splits a year into `19`/`28`, and reading those as 十九/二十八 dates the row to the wrong sentence, while a stranded 十/百 in the copy is just another unmatched char that `align()` already interpolates between its two real anchors. `npm run check` statically guards the four wirings (both tables identical, both sides folded on both paths). ## Script Rules

Script file naming is fixed: the two-line hook lives in `episodes/<书名>/script-hook.csv`, the body voiceover copy in `episodes/<书名>/script-body.csv`. Never reintroduce a bare `script.csv` / `script-hook.md` / `文案.md` as the machine source of truth; any annotated source must be converted to `script-body.csv` before rendering.

Read `docs/book-video-playbook.md` before drafting. The first line must immediately create resonance. Use short, natural lines and concrete scenes. Let the book support the viewer's emotion instead of becoming an academic summary. Avoid “你是不是”, “不是……而是……” formulas, mechanical parallelism, arrogant instruction, and CTA language. End with emotional aftertaste.

Draft every opening against the user's 5-question hook standard and self-check it before showing the script: does it concern the viewer, spare them a loss, contradict what they assumed, echo something they have lived, and leave a gap they want closed? Rewrite anything scoring fewer than 3. Default shape is “golden line first, then the cost”: put the core line in the first body row and follow it with the time-drop. Echo that same line at the end so the opening's rule becomes closing aftertaste. The cover hook, the opening 3 seconds, and the post title must carry one theme — but never print the golden line itself on the cover, because a cover is read, not heard, and the line is the answer; use the question-shaped or cost-shaped variant instead. Keep the cover hook within the 22-character `COVER_HOOK` limit in `scripts/make_episode_cover.py`, and record `cover_hook` / `cover_tag` / `hook_design` in `episodes/<book>/brief.json` instead of passing them only on the render command line, where the next render silently loses them.
Every hook is the same two-line device — golden line, then the cost turned back on the viewer — so the **second line's opener collapses onto one gesture** long before any single episode looks wrong. `check-episode-delivery.py` cannot see this and neither can the five-question self-check: the copy is on disk, within the line budget, and every gate stayed green while 21 of 30 promoted hooks opened their second line with 「我合上书」 or 「我读完…」 (census on 2026-10-03, 70 % in one family). `scripts/check-hook-openers.py` is the assertion: it classifies every shipped second line into device families (`READING_ACT`, `QUOTED_LINE`, else a literal 4-char bucket so a new concentration surfaces without editing code) and reds any family over `CAP` of the corpus; `promote-hook-draft.py` now calls `plan_problems()` **before** it writes, so a batch that would push an overloaded family is refused at the draft stage instead of being caught by ear forty episodes later. `--plan <书名…>` is the drafting-time call, and because already-written drafts can still be pre-recording, `plan_problems` excludes the planned books from the corpus first — counting 《麦克白》's own 「我合上书」 against itself makes the share rise every time you check, which is a gate that gets stricter the more you use it. Overloaded families are retired for new work; bypass only with `--allow-overloaded-opener` plus an `opener_override_note` in the draft, so the exception is on disk rather than in chat. Recorded audio is frozen — the user's own voice is not a re-renderable artifact — so a rewrite may touch only episodes with no `钩子.mp3` yet; the 12 already recorded keep their lines and the census shows them as a permanent red that says *stop adding*, not *go fix*. The same script's `--cover-echo` mode owns a second defect it found on the way: the cover hook and the second line must carry **one theme** (AGENTS.md above), but when they share a run of 4+ characters the viewer reads the phrase on the cover and then hears it in the first five seconds, which turns the cost line into a restatement — 《卡利古拉》 shipped cover 「都过去了这句你说过几回」 over line 2 「那句都过去了，我对自己说过多少次」. `plan_problems` refuses that at write time, and `--cover-echo` marks already-recorded episodes 🔒/exit-0 instead of 🔴/exit-1, because a frozen take is history, not a backlog. When line 2 is rewritten before recording, `cover_hook` is re-checked against the new wording (it derives from the cost line, not the golden line) and the old line is kept as `line2_rewrite.from`.

When WeChat Reading is available, consult its book details, popular highlights, and public reviews before drafting so the script has concrete material and a reliable emotional entry point. Use the Skill to inform the writing, not to copy long excerpts or replace independent judgment.

Hand-patching was tried first and is the wrong tool: the file has 250 throw sites and is being edited by other sessions, so a hand-made copy is both an expired snapshot and whack-a-mole — run 3 on 2026-10-09 died at a *third* site (`:2334`, the static name-guard) after two were already downgraded. Two mechanical traps in the copy: ESM resolves relative specifiers against the **copy's** directory, not the cwd, so the one `await import("./lib/intro-page-pairing.mjs")` must be re-pointed at `../scripts/lib/…` (only the real statement — the string literal several lines below compares *production's* text, and rewriting it makes the probe record a false red); and the file's shebang must be dropped or it lands on line 4 and is a syntax error. Then report both numbers — the production red and the probe's collected downstream list. Never present the probe's `book-video checks: ok` as a pass: it is a measurement of what the red was hiding, not a green. The probe is safe to run alongside renders because `ROOT` is `process.cwd()` and its HyperFrames template copy goes to `fs.mkdtempSync(os.tmpdir()/…)`, so it never touches a concurrent session's `tmp/<书名>_tpl`. What it found the same day is worth the recipe: the guard at `:2284` pinned the cover red's wording as 「单行装得下却折了行」 while the gate and its test had both been renamed to 「书名折了行」 on 10-08 15:56 — the pin lagged, and because it sits *below* the fail-fast it had been an unreachable landmine for a day. A judgement's wording and the token that pins it move in one edit, or the check cannot even reach its own staleness.

A shell line that reads fine in one session can abort a whole render in another, because macOS system bash (3.2.57 here) **folds the lead byte of a multibyte character into the variable name**: `echo "组成指纹 $before，…"` under `set -u` looks up `before\xef`, not `before`, and dies with `line 109: before？: unbound variable`. This is locale-dependent — `LC_ALL=C` parses it correctly while `LC_ALL=en_US.UTF-8` and `LC_ALL=zh_CN.UTF-8` both die (measured on this machine, three invocations of the same two-line script), which is why the same `echo` printed a clean 组成指纹 in five episodes and killed 《无名的裘德》 at 2026-10-08 11:13: its hook.mp4 had just rendered, no gate ran, and no final was assembled. So **brace every `$var` that a full-width character follows** (`${before}，`), and do not treat "this line worked yesterday" as evidence — yesterday's shell may have had a different locale. `scripts/check.mjs` scans every `scripts/*.sh` for a bare `$name` followed by a non-ASCII character (after stripping `${…}` and `$(…)`), reddens on any hit, self-tests by re-injecting the withdrawn shape into its own predicate, and pins the two fixed lines (`组成指纹 ${before}，`, `rc=${rc_render}（`) by text so a revert names the incident it re-opens. The second of those sits in a `[FATAL]` branch, where the crash would have eaten the diagnosis along with the render.
