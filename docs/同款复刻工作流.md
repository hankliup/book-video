# 同款复刻工作流（参考片拆解 → 复刻成片）

2026-10-07 由《高手布局》一期全程实战沉淀（拆解 → 短版脚本 → 配音对轴 → 选图 → 渲染 → 14 道门禁全绿）。适用场景：用户给一条参考视频（竞品/别号），要求「拆解这条视频」或「照这个结构做一条」。

本文是操作序列与踩坑账。**生产红线（语速、档位、裁切秒数、门禁阈值）一律以可执行文件为真源**——`scripts/lib/script-policy.mjs`、`scripts/lib/intro-template.json`、`scripts/lib/water-ripple.json`、`scripts/lib/book-cover.json`——本文只做索引，不手抄数字。

## 阶段 0：参考片技术拆解（全部实测，不靠目测）

1. **规格**：`ffprobe` 拿分辨率/帧率/时长/码率/音轨；`volumedetect` 拿响度（均值/峰值）。下载版码率偏低不代表原片质量。
2. **切点与运动**：`ffmpeg fps=6` 抽 90x120 灰度帧 → numpy 逐帧平均绝对差曲线。峰 = 切点，峰宽 ≈ 叠化时长；场景内基线 0.5–2.5 = 会动的视频素材，≈0 = 静图；整段持续高变化 = 快闪/全帧换画。这一步的数字是后面「复刻哪段节奏」的依据，比逐帧肉眼看可靠。
3. **旁白**：`whisper-cli`（仓库模型）转写 → 确认「字幕文案 = 配音稿」、实测语速（字/秒）、BGM 是否全程铺底（`silencedetect -35dB d=0.4` 找不到静音段 = 有垫乐）。同音误听正常。
4. **分层拆解**：背景层（素材类型/调色）/固定文字层（书名卡出现时机）/字幕层（单双语、字体、对轴方式）/水印残留（模板工具徽标、免责声明行、@水印——复刻必须全部清除）。
5. **产出**：`docs/拆解-<账号>-<书名>-<结构名>.md`，附 beat sheet（结构模板）与避坑清单。

## 阶段 1：同款脚本

- **口径判断**：同款时长落哪一档由 `scripts/lib/script-policy.mjs` 的预设决定；短版是例外，用户点名要短（同款 45–60s 即是）才传 `--short`，并留痕说明。
- ⚠️ **新期第一坑（2026-10-07 高手布局）**：`resolveScriptVersion` 只认 `brief.json` 与历史 `script-body.csv`，**不认 `script-body.csv`**。新期必须先建 `brief.json`（至少 `display_title`/`author`/`scriptVersion`），否则校验报 `No script rows found for version A_reference_like`。
- 校验通过（0 错误 0 警告）才发给用户；交付块惯例（一个代码块、首行《书名》、可整体贴进剪映）见 playbook 工作流第 4 步。钩子另出 2 行（`script-hook.csv`），不得重复正文第一句。

## 阶段 2：配音与字幕轴

- **落位**：`episodes/<书名>/钩子.mp3`（episode 根目录，`prepare-hook-segment.sh` 硬编码约定）+ `episodes/<书名>/配音.mp3`。
- **story 预设**：`node scripts/process-voiceover.mjs <入> <出> story` → `audio/body-voiceover.mp3`，再 cp 一份为 `audio/body-voiceover-story.mp3`（两个名字同内容，不同消费者读不同名；hook 同理）。ffmpeg 8.1 下对 24kHz 源会打印 `lowpass … Invalid frequency`（14500 超奈奎斯特）但链路继续、loudnorm 仍生效——历史各期同一行为，不修。
- **正文五步**（顺序不可换，依据见 AGENTS.md 生产门 3）：`asr-segmented.mjs` → `asr-to-simplified.py` → `create-body-timings-precise.mjs` → `snap-body-timings-vad.py --apply` → `audit-caption-axis.py --apply`。
- **判收**：snap 报「未盖住自身语音 0 行 / 末条 end÷时长 = 1.000」；`audit --json` 的 `residual = 0`。
- **同音字 ≠ 文案分歧**：ASR 把「越老实」听成「月老师」这类不改 CSV（CSV 是字幕真源）；判据是 token 匹配全部锚住、零弱锚点。真文本分歧才先改 CSV 再继续。

## 阶段 3：选图（全尺寸目检是主工序，检索只是供给）

- **分镜**：正文行按语义归层（《高手布局》20 行 → result-bridge + 8 个 atmosphere 层），钩子 2 拍；每层一个 Pexels 查询，查询词主动避开可读文字源（店招、车牌、屏幕、表盘）。
- **检索**：逐拍 `python3 scripts/pexels_candidates.py --out tmp/<期>-cand/<beat> --cache tmp/<期>-cand/cache --per-query 4 --exclude-used "<query>"`（钩子拍必带 `--exclude-used`；正文拍也带）。exit 3 = 有检索词网络失败，带 cache 重跑那几个词，**不是**「无可用」。
- **目检（逐张全尺寸）**：三类全局废（人脸 / 可读招牌文字 / 摆拍道具）+ 疑似水印签名 + 纯跑偏命中。2026-10-07 实例：怀表表盘上的可读品牌字 → `scripts/reject-pexels-photo.py <id> --reason "…可读…文字…"` 入持久名单（理由必须含「招牌/文字/人脸/摆拍」类关键词，工具否则拒收）；整组黑白照与全集色彩不搭 → 换查询重搜，不硬凑。
- **锁单**：picks 文件 `[{name, beat, cell, note}]`（cell = cand.json 下标，不手抄 id；钩子条目加 `"dir": "images-hook"`；result-bridge 也占一条）→ `python3 scripts/lock-pexels-candidates.py "<书名>" tmp/<期>-picks.json --apply`。
- **取图调色**：正文 `IMAGES_SUBDIR=images-body python3 scripts/fetch-pexels-by-id.py "episodes/<书名>" "data/<书名>_pexels_ids.json" --segment=body` → `grade-atmosphere-images.py --restore` → `grade-atmosphere-images.py` → `fix-bright-regions.py`。grade 打印 ⚠️ 并 exit 1 是「要补压」的信号，不是中断点。钩子侧整链路（取图/调色/溯源行/门禁/钩子轴重跑）一个脚本：`bash scripts/prepare-hook-segment.sh "<书名>"`（也要干净环境，见阶段 4）。
- **scene-map.json**：首层 `static result-bridge` 只盖第 1 行，atmosphere 层 contiguous 到末行；motion 参数照抄最近已交付期。
- **收口**：`write-prompts-csv.py "<书名>" --apply`；`brief.json` 声明 `"image_pipeline": "pexels-1024"`；`check-image-provenance.py "<书名>"` 必须 ✅。钩子图未取时它红 `images-hook` 两条——那是还没跑 prepare 的正常中间态，跑完即绿。

## 阶段 4：渲染与交付

1. `node scripts/create-episode-preview.mjs "<书名>"` → 打印 `tmp/preview-book-<hash>`。slug 由算法决定，**不可从 `ls tmp/` 猜**。
2. **渲染+装配+门禁一条龙**：`bash scripts/render-hook-batch.sh "<书名>"`，逐期日志在 `tmp/render-b3/<书名>.log`，成败只认日志末尾「交付门禁汇总」块，不信退出码。
   - ⚠️ **必须干净环境**（本机 bash 3.2 + UTF-8 locale 会把紧跟 `$var` 的全角标点吃进变量名报 `unbound variable`；2026-10-06《李尔王》、2026-10-07《高手布局》两次实锤，特征 = 某段 mp4 已渲出但 provenance 台账未记）：
     ```
     env -i PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin HOME="$HOME" TMPDIR="${TMPDIR:-/tmp}" LC_ALL=C /bin/bash scripts/render-hook-batch.sh "<书名>"
     ```
   - ⚠️ **兜底渲染器没有 `--help`**：裸跑 `render_scene_map_template_fallback.py` 会按默认 EPISODE 直接开始渲**别的期**（2026-10-07 实测，靠管道 head 截断才没写脏盘；事后 `find <别期> -newermt` 验证无损）。手动单跑必须 `EPISODE=<书名>` 前缀；成片超 60s 加 `ALLOW_OVER_60_SECONDS=1`（《高手布局》65.23s）。
   - BGM：`assets/bgm/` 目录枚举解析（多曲时 `BGM=<文件名>` 指定或问用户），混音 0.32 音量、-14 LUFS，由装配层自动完成。
3. **门禁红灯修复循环**：本期唯一红灯 = 缺 `book-cover.jpg`（正文起幅封面卡）→ `python3 scripts/fetch-book-cover.py "<书名>"`（微信读书优先）→ 整体重跑批渲。
4. **交付后自证**：`ffmpeg -y -i <final> -t <钩子时长> -c:v libx264 -g 1 -crf 10 -an tmp/<期>-delivered-hook-window.mp4` → `check-render-artifacts.py <窗>` **不带 --composition** 严格扫，必须 clean（0 脉冲）。
5. **交付消息**：成片以绝对路径 Markdown 媒体内嵌（AGENTS.md 生产门 6），附规格与结构时间轴。

## 一期交付后的资产清单（episodes/<书名>/）

| 类别 | 文件 |
|---|---|
| 文案 | `script-hook.csv` `script-body.csv` `brief.json` `scene-map.json` `prompts.csv` `book-cover.jpg` |
| 音频 | 根目录 `钩子.mp3` `配音.mp3`（原始）；`audio/` 两段 `-voiceover.mp3` + `-voiceover-story.mp3` + `asr/` + `body-timings.json` `hook-timings.json` |
| 图像 | `images-body/`（含 `_raw/` `_provenance.json`）`images-hook/`（同）`pexels-fetch-log-*.jsonl`；锁定清单在 `data/<书名>_pexels_ids.json` |
| 成片 | `renders/<书名>-final.mp4` + `renders/hook.provenance.json` `renders/intro.provenance.json` |

根目录两段原始配音和 `audio/` 双名副本都保留：原始是用户交付物，双名是不同消费者的既定读取路径，删任何一个都会断后续重渲链路。
