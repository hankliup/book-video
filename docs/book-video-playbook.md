# Book Video 生产手册

这是唯一有效的图书带货视频生产 SOP。共享模板位于 `templates/shared-video-template/`；每期只替换书籍信息、文案、Pexels 背景图、正文口播和 BGM。

> 入口变体：用户给一条参考视频要求「拆解」或「照做一条」时，先走 `docs/同款复刻工作流.md`（拆解 → 同款脚本 → 同一条渲染与门禁链），本文其余步骤照常适用。

## 工作流

1. 初始化：Agent 先定位当前仓库根目录并运行 `node scripts/init.mjs`，一次性检查 Codex 的 HyperFrames/imagegen 能力、Node.js、FFmpeg、`whisper-cli` 和 Whisper 模型。不要根据 FFmpeg/FFprobe 的版本输出首行判断是否安装，统一以检查命令退出状态为准。缺少本机运行时依赖时集中说明并征得一次同意，再负责安装。模型按文件大小确认，不用目录列表判断。HyperFrames 首次使用可能需要 npm registry；网络被拦截时，Agent 直接通过执行工具申请网络权限并自动重试，不重复询问用户。微信读书 Skill 自动安装启用；只有初始化结果明确显示缺少 API Key 时询问用户，确认后打开官网，明确提示用户获取 Key 后回到本对话发给 Agent，再安全写入本地配置；已显示 `weread: enabled` 时不得重复询问。
2. 选书：读取本地候选池；没有候选时先询问偏好，再搜索候选书。微信读书 Skill 已安装且可用时，优先灵活使用它获取书籍详情、评分、热门划线和公开书评；没有有效结果时再补充公开资料或用户提供的信息。搜索结果必须先全量写入本地 `data/book-pipeline.csv`，再从已记录的书目中选择五本并标出首选。
3. 书目确认：确认书名、作者、版本和 `display_title`。
4. 文案确认：先阅读书籍元数据、热门划线和公开书评等可用研究材料，再按本文的脚本原则只写一版文案。微信读书内容用于提炼情绪入口和事实背景，不直接复制长段落或整篇书评。文案在消息中用一个 Markdown 代码块完整展示可配音内容。代码块第一行写 `《书名》`，后面紧接全部朗读正文，不加入 CSV 字段、序号、作者标签、时间戳或解释；用户应能一次性复制代码块到剪映生成音频。同时保存为 `script-body.csv` 作为机器处理真源，等待用户确认后再继续。
   文案长度：默认长版，成片 4–5 分钟，正文约 1100–1450 字；短版（总计 18–20 行含书名、硬上限 22 行、正文 180–300 字、约 1 分钟）只在用户明确要短版时用，并给 `validate-script.mjs` 传 `--short`。字数换算成秒用的是实测语速 `NARRATION_RATE_CPS`，不是拍脑袋的数：取 `episodes/待上传/` 下 99 期已交付成片，ffprobe 量到的成片时长减去 3.0s 片头再除以该期 `script-body.csv` 正文字数，中位 4.69 字/秒（p10–p90 4.42–5.05，最慢 4.08，最快 5.90）。两条口径与这个常数只有一份真源——`scripts/lib/script-policy.mjs` 的 `SCRIPT_LENGTH_PRESETS` / `DEFAULT_SCRIPT_PRESET` / `NARRATION_RATE_CPS`，硬限制是同文件的 `MAX_BODY_SCRIPT_LINES`（正文最多 200 行）和 `MAX_BODY_SCRIPT_CHARS`（正文约 10000 汉字），本文不复述数字。
   这条默认值的来历：99 期已交付成片里 98 期在 797 字以上、中位 1220 字（约 4.3 分钟），house style 就是长版。写稿门禁一度把「18–20 行」写成推荐目标，于是 2026-09-29《穆斯林的葬礼》初稿拿到 211 字（约 0.8 分钟）就发了出去——把下限当目标用了。现在 `validate-script.mjs` 会回报 `lengthBand` 与 `estimatedMinutes`：默认按长版校验，短版只出 note 不判红（否则 33 期 800–1050 字的历史成片会一起判红），低于 180 字才判失败。文案写入临时 `script-body.csv` 后，必须先运行 `node scripts/validate-script.mjs "<book>"`；未通过时由 Agent 内部缩短，不能先发给用户确认，也不能等到配音或最终渲染阶段才处理。
5. 图片制作：背景图一律来自 Pexels 实拍，不走 AI 出图。按叙事段落写检索词（`orientation=portrait`），用 `scripts/fetch-pexels-images.mjs` 出候选（正文段 `IMAGES_SUBDIR=images-body`、钩子段 `IMAGES_SUBDIR=images-hook`，两张画幅都用 `TARGET_SIZE=1024x1365`），并且**每次取图都带 `PROVENANCE_OUT=<episode>/pexels-fetch-log.jsonl`**：photo id、摄影师、原图链接由脚本当场写盘，不靠事后回忆（《涅朵奇卡》2026-10-01 就因为先出图后补溯源、tmp 被清，13 张已落地的图再也取不回 photo id，只能整批重取）。候选拼联系表只用来筛掉明显不合适的；**定稿前必须逐张按原始尺寸打开看一遍**，找的是「这个故事的时间地点不可能有的东西」——楼梯口发光的绿色 EXIT 指示牌、雪夜里停成一排的现代汽车、招牌、天线、塑料椅。这类穿帮量不出来：`check-image-provenance.py` 查的是尺寸、亮度和溯源，13 秒的 EXIT 和 48 秒的停车场能让所有数字门禁全绿。选定后居中裁成 1024x1365（3:4，取 `src.original`，不要用 Pexels 预置的 810px portrait），再跑 `scripts/grade-atmosphere-images.py` 统一调色和 `scripts/fix-bright-regions.py` 补压亮区；调色是原地覆盖的，换图后先 `--restore` 再从 `_raw/` 整批重跑一遍，只补新图会让全组跳色。选型看光线、色温和留白，不看字面图解；一张图对应一个叙事段落，允许关键意象（如贯穿全书的那片叶子）在非相邻段落复用。清单落 `data/<书名>_pexels_ids.json`，图层区间落 `episodes/<书名>/scene-map.json`（首层必须是 static `result-bridge`，且与片头结果页同一张图），每张图的 photo id、摄影师、链接、裁切与调色口径写进 `prompts.csv`，`brief.json` 声明 `"image_pipeline": "pexels-1024"`。交付前跑 `python3 scripts/check-image-provenance.py "<书名>"`：缺溯源、图层指向不存在的文件、图小于 720x960（渲染会上采样发糊）、没跑过调色，都会红灯。**清单说换图、盘上却还留着旧图，是第三种方向**：文件在、尺寸对、也调过色，所以「清单有 id 但盘上没落盘」和「盘上有图但没溯源」两道都看不见它。2026-10-03《偏跟山过不去》就是这一条——重锁后 `fetch-pexels-by-id.py` 遇到同名文件直接跳过，打印「完成 1/1」却什么都没写，重渲把**上一张**照片原样放上屏，八道门全绿。现在身份靠标记而不是靠猜：每次成功取图都把 `photo_id`、`_raw/` 底图 sha256、落地那一刻成片的 sha256 和实际拉到的源图链接写进 `images-hook/_provenance.json`（正文段同理），门禁读这份标记——标记 id 与清单不符、「清单里这张没有标记条目」、「`_raw/` 丢了」、「`_raw/` 字节和标记记的不一致」（这条尤其要紧：`grade-atmosphere-images.py --restore` 会把 `_raw/` 直接拷回成片，一份陈底图能悄悄把废掉的图复活）都会红灯。`lock-pexels-candidates.py` 在换图时记 `replaces_photo_id`，取图脚本据此打「覆盖重取」而不是「跳过」；取图也不再拿「文件已存在」当成功——没有标记就明说无法证明它就是那张照片，标记不符就重取。要逐像素证明「盘上图 = 清单那张照片」，跑 `scripts/verify-pexels-fetch.py`（或 `check-episode-delivery.py --verify-photos`）：它按标记里的 `image_url` 重下源图、用 fetcher 同一份 `scripts/lib/pexels_crop.py` 裁切、与 `_raw/` 比，CDN 只回低分辨率时它判「未能证明」而不是「不符」，所以默认不开、要联网才开。**不要用感知哈希替代这条链**：同一张照片调色前后 dHash 距离实测最大 31，两张不同照片最小只有 12，调色是原地覆盖的，哈希在成片上根本分不开「同一张调过色」和「另一张」；可核对的链路是 清单 id → `_provenance.json` → `_raw` sha256 → 成片图 → 交付帧（`scripts/check-hook-frame-match.py`，交付门禁第 9 道，有 `script-hook.csv` 就自动跑，专治「组合成改了却没重渲、成片还是旧像素」）。标记只在**已经有标记**的目录里强制，历史剧集不必回改，免得把门禁变成一百期的考古工程。**钩子段还多一条跨期红线：这张照片任何一期都没上过屏。** 单期门禁看不见它——一张照片在 A 期正文、B 期钩子各出现一次，两边各自都合法；而 113 期钩子回补把「一百多期共用一个素材库」变成了常态，实测 10 期 11 张钩子图撞了别期正文，八道门全绿。判据只有一个真源 `scripts/lib/pexels_index.py`（photo id → 期·段·文件，一次进程内建一次），三道防线共用：检索阶段 `scripts/pexels_candidates.py --exclude-used` 直接把已上屏的 id 丢掉（钩子段挑图必带），锁定阶段 `lock-pexels-candidates.py` / `lock-pexels-selection.py` 拒绝把用过的照片锁进钩子段（有意的回扣要 `--allow-used-elsewhere` 并在 picks 里写 `reason`），交付阶段 `check-image-provenance.py` 把已经上屏的撞图判红并点名是哪几层。`npm run check` 静态盯这三道还都接在 lib 上，也盯 `foreign_uses()` 只在 lib 里定义一次。`--exclude-used` 看不见**人工否决但从未投放**的照片，于是同一张废图每批都会重新端上来一次：2026-10-03 第四批里，同一次大理稻田亲子旅拍的 6 帧（Pexels 的 alt 是 "animals, Beautiful scenery, beautiful woman" 这种乱标签，任何氛围词都能召回）出现在 15 个候选批次，带一排可读公示栏的中式村委长廊 #39854273 出现在 18 个批次。会话里的「这张不行」不是管线状态，所以它落成了 `data/pexels-rejected.json`，唯一读入口 `scripts/lib/pexels_reject.py`：检索阶段默认丢掉名单里的 id（`--ignore-rejected` 只用来复核某条否决本身对不对），两个 lock 脚本都拒绝把名单里的图锁进任何段。**豁免只有一条**：这张图本来就在本期自己的清单里——重锁一段时原样搬回来的条目不能被一份后来长大的名单打死，而撤一张已经上屏的图走「重选＋重渲」，从来不是改名单。写入用 `scripts/reject-pexels-photo.py`，它拒收两种理由：不是「人脸／可辨认招牌／生活方式与道具摆拍」这三类**对任何一期都不成立**的缺陷，以及已经上过屏的 id。**只收全局废图**：江南白墙青瓦对西北村庄那期是缺陷，对另一期可能就是正解，按期拉黑只会让检索池一批比一批小。`npm run check` 静态盯这四个接线，并逐条复查名单本身（理由必须属于那三类、被拉黑的 id 必须从未投放）。同一份「检索失败不等于没有图」的教训也钉进了 `pexels_candidates.py`：代理隧道抖动（`Tunnel connection failed: 503`）现在先退避重试两次再把这个词判死，且只要还有词失败就以退出码 3 收场并列出是哪几个词——第四批有 3 个 beat 因为一次 503 只剩 3 张候选，目检据此写了「无可用」，把一次网络抖动误读成「Pexels 没有这种图」，代价是整期重检索。只锁钩子段时 manifest 和 `write-prompts-csv.py` 都是按段合并、不整份覆盖（《秋园》2026-10-02 一次钩子重锁抹掉了 23 行正文溯源）。只有当某个叙事段落确实找不到任何能承载它的 Pexels 照片时，才允许用内置出图补那一张，并在 `prompts.csv` 里写明是降级；历史剧集不要求回改。
  **锁定的合并语义是「按段替换」，补锁一张必须带全该段（2026-10-07）。** `lock-pexels-candidates.py --apply` 把 picks 里出现的段整段替换成 picks 内容——给已有 13 张正文图的期只递 1 条 result-bridge 的 picks，其余 12 条正文条目会被这次「补锁」静默抹掉（输出里的「另有 N 条其他段选型原样保留」只在提示别的段）。正确做法：picks 里用「沿用」条目把该段已有选型一并带上。清单一旦损坏，从**取图日志**程序化重建（`pexels-fetch-log-body.jsonl` 的 `pexelsId`/`photographer`/`url` 是取图当场写盘的事实，过滤掉 `skipped` 行按 file 去重），不手抄 photo id；重建后立刻跑 `check-image-provenance.py` 用 `_provenance.json` 标记交叉验证。scene-map 的回扣层 `reuse_of` 一律写目录限定名（`images-body/atmosphere-2`）：钩子段与正文段都从 atmosphere-1 起编号，裸名在 write-prompts-csv 的同名索引里会被**另一段**的同名条目吃掉（《乞力马扎罗的雪》2026-10-07：正文回扣解析到了钩子的 #5994745）；裸名只做历史 scene-map 的兼容。回扣层还要落一份字节级文件副本（`atmosphere-14.png` = `atmosphere-2.png` 连同 `_raw/` 底图），渲染器只认 `{name}.png`。**换过 `images-body/result-bridge.png` 就必须重渲片头**：`scripts/create-episode-preview.mjs` 把它拷成 `tmp/<期>/intro/media/pages/result.png`，片头结果页定格用的就是这一张；只换正文底图而不重跑 `npx --yes hyperframes@0.7.33 render`，正文首帧与片头 3.0s 定格会是两张不同的图，兜底渲染器的切点跳变门禁会判红（报的却是「接进来的多半不是本期的片头」，容易查错方向）。《围城》2026-09-27 由 AI 出图改 Pexels 实拍时踩过：先重拷 `result.png` 重渲 intro，再跑正文渲染。
6. 音频制作：接收用户的正文口播 MP3，应用故事感旁白处理；没有音频时只出纯画面预览。
7. 时间轴制作：字幕轴必须由 ASR **token 时间戳**推出，不能靠静音间隙顺序铺满。长配音的标准五步：`node scripts/asr-segmented.mjs "<书名>" episodes/<书名>/audio/body-voiceover-story.mp3`（整段直跑 Whisper 会在 30s 窗口上漏识、边界漂移）→ `python3 scripts/asr-to-simplified.py episodes/<书名>/audio/asr/body.json`（后段整段吐繁体时 token-LCS 学不全繁→简，跳过这步匹配率只有 61.4%，跑完 77.1%）→ `node scripts/create-body-timings-precise.mjs "<书名>"`（token-LCS + gap-aware）→ `python3 scripts/snap-body-timings-vad.py "<书名>" --apply`（逐行把字幕窗拉到「这一行自己的字真正被念出来」的区间）→ `python3 scripts/audit-caption-axis.py "<书名>" --apply`，用 −50dB 能量边界逐行收掉四类残留缺陷：行首落后（连续语音已开口 ≥0.35s 才出字幕）、行内空窗（配音没停字幕却掉了）、读不完（窗口短于字数÷语速）、行尾拖（end 压在真停顿里）。**行首默认不动**，只有后两类命中才动。`script-body.csv` 始终是字幕文本真源；ASR 只出时间，绝不进字幕文本。`create-body-timings.mjs` 的静音铺满轴只作为 token 不可用时的降级，降级即须在交付前用第 9 步的轴门禁复核（《茶馆》2026-09-28 铺满轴末条覆盖比 0.998、行间零空隙，看起来完美，实际第 38-45 行比语音早 14-16 秒）。
   token 轴之后为什么还要覆盖这道：Whisper.cpp 没有 DTW（`t_dtw` 恒为 −1），窗口内的 token 时间是模型预测后线性摊平的，**行归属对了也可能整行差 1–3 秒**——《恶女的告白》2026-09-28 交付的正是 token 轴，88 行铺满 227.6s、前六道门禁全绿，仍有 40 行字幕没盖住它自己那句话（|Δstart| 中位 3.04s、最大 11.82s）。`snap-body-timings-vad.py` 用两方证据逐行定出「可听语音窗」：ASR 字符顺序把这一行钉到 token（在锚点之间线性插值，绝不跳到下一个匹配块），波形能量突发把钉住的头尾钉到听得见的地方（自适应门限 `p25 + 0.55*(p90 − p25)`，合并 <0.18s 的间隙、丢弃 <0.15s 的突发）。行首只允许移进真静音空隙；某行需要更多时间时，先回收上一行超出自身语音的余量（最多 0.60s 的停留），再让下一行的行首；任何行不得短于 0.90s 可读窗。「可听语音窗」的唯一真源是 `scripts/lib/caption_speech.py`，修轴脚本和第 9 步的门禁都读它，防止两边口径漂移。
   **字符流里只许有「被念出来的字」（2026-10-07《无名的裘德》行 103/129）**：whisper.cpp 会吐一族控制 token——`[_TT_数字]`（模型自己预测的时间戳）、`[_BEG_]`、`[_EOT_]`、`[_EP_数字]`、`[zh]`。两侧以前各写一条**漏了闭合 `]`** 的正则（Python `re.match(r"^\[[_A-Z]+\d*$")`、Node `/^\[[_A-Z]+\d*$/u`），于是以 `[` 开头的 token 一个都没被剔掉：60 份 body.json 里实测 `[_TT_…]` 2636 个、`[_BEG_]` 510 个、`[_EOT_]` 10 个全部进了流。危害分两处——Node 侧这些零时长/段界伪 token 会改写 `gapOnset`，而行首正是吸附到 gapOnset 上的；Python 侧更狠，`clean()` 剥掉方括号却留下下划线和字母，还把数字折成汉字，于是 `[_TT_628]` 贡献 `_TT_六二八` 七个幽灵字符，数字一折就和「文案里真念出来的数字」撞成同一串字，抢走一次**时刻是段界而不是说话点**的假锚点（全库 token 起始时刻倒退 165 处里 139 处属于它们，剔完剩 26）。现在形状只有一个真源：`CONTROL_TOKEN = ^\s*\[[^\]]*\]\s*$`（「整对括号、括号内没有别的括号」），写成前缀表就是下一次静默失效——`_TT_` 的后缀形状以后还会加。两侧 pattern 文本由 `npm run check` 抠出来逐字比相同，而且**拿去真匹配一遍**：必须命中全部六个实测形态加带空白的变体，必须不命中 他/x/`[x`/你好/`[]x`；只看「含不含方括号」会放行旧 bug，因为它的 `]` 在字符类里、整条式子照样匹配不上 `[_TT_628]`。`scripts/tests/test-positional-anchor.py` ①② 用真 token 文本把两个方向都复现了，包括「旧口径确实让幽灵数字抢了一次命中」。
   **听见了、只是字写错的行，不算「没有锚点」**：difflib 的匹配块只覆盖字面命中，同音错字会在两块真命中之间留下空档，以前一律线性内插——而内插假设每个音节等长，同音错字恰恰证明音节是逐个存在的。现在文案侧与 ASR 侧在两个真锚点之间**缺的字符数相等**（`gs == ga > 0`）时，第 i 个缺口字符取第 i 个缺口 token 自己的 from/to（按位对位 / positional anchor），并置 `flags[k]`；`matched` 仍只数字面命中，所以门禁日志里的「ASR 字序命中 X / Y」和历史可比。数量不等（漏听、多听、吞字）一律不猜：宁可内插不可编时刻。这一判按**空档整体**决定，绝不逐字符挑（实测 136 期里「同一段既对位又内插」0 处），这也是「把近音锚点并进内插梯级」那一行今天必然是 no-op 的原因（`tmp/probe-ladder-noop.py`：逐字符 0 差异）——它留在那里是将来把对位改成逐字符挑选时的地板，它描述的那种越过去是第一版 off-by-one 的真实形状（键从 `b0.a` 起算，会把时刻盖到上一个真命中块自己的字符上）。那个 off-by-one 也是第一版全库 A/B 报出「46 行获得锚点」的来源：被污染的对照，不是本改动的效果面，所以 test ⑤ 和 check.mjs 对键起点的静态断言两样都得在。全库实测（136 期）：锚点薄弱行 **79 → 7**，轴判红 124 → 128、成片字幕轨判红 112 → 111（26 行换了边：新增 11、转绿 19）。三部已交付片由绿转红——《乱世佳人》行 60/71 行首比自身语音晚 0.87s / 0.80s，《秘密花园》行 81 晚 0.61s 加行 129 密度，《荆棘鸟》行 34 密度——这是口径第一次量到它以前只能弃权的错位，不是新缺陷，修法每期一次 re-snap + re-audit + 重渲，绝不是放宽阈值。《无名的裘德》两行新旧都红：旧口径只能说「窗内语音 10% <45%」，新口径能说「字幕比 浴 开口晚 0.59s」——命名出来才谈得上让规则 D2 和覆盖 pass 去修。同一门禁的可读性修正：T2 只报**被跨过的那一条**，以前恒定的「窗内语音 X% <45%」会让被富余停留豁免的行显示成「窗内语音 100% <45%」，把人推去追一条并没有红的判据。
   **覆盖必须在能量审计之前跑，不能反过来**：审计的 C 规则裁掉的正是覆盖加上的那种尾部停留，先审计会立刻被重新撑开；先覆盖，审计才能自由裁尾、补空窗而不揭开任何一行（《恶女的告白》实测：`audit-caption-axis.py --apply` 改完 31 行之后再跑 `check-caption-speech-align.py`，仍是 0 红灯）。
   **单行语音窗错但别的行都对时改 ASR，不改轴**：Whisper 长段内部的 token 时间是线性摊平的，一段里可能只有某一行的窗口整体偏到静音上。用 `python3 scripts/retime-asr-segments.py "<书名>" --rows <行号>` 只把这一段的音频（含小余量）切出来重识别，采纳条件是新文本仍覆盖本段字符、且落在真静音里的字符数严格减少；脚本把决策写进该段的 `retime` 字段并留 `.pre-retime` 备份，所以 `create-body-timings-precise.mjs --verify` 仍能自证。之后按顺序重跑 precise → snap → audit 并重渲。两种"顺手修法"是禁的：为了修一行把整篇 ASR 换成更短的 segment target 重跑（《追忆似水年华》2026-09-28 这样跑完 45/92 行丢锚点、变成 0.3 秒假铺），以及用停顿吸附把某行的 `end` 顶到后面的静音里（那只是把缺陷镜像了一遍——字幕停在 0.98 秒的真静音上，还吞掉下一行的语音）。
8. 对齐渲染：裁剪 BGM 到视频长度并完成混音。**段渲染的两道前置（2026-10-06）：**
   ① 钩子/片头段每渲完一轮必须过 `python3 scripts/check-render-artifacts.py <段mp4> --composition <本期工程 index.html>`（`scripts/render-hook-batch.sh` 已自动跑，最多六轮，扫红即删掉产物与账本重渲，扫描发生在落 provenance do grep …; sleep; done` 监视进程**不算忙**（13:47 那次就是被它空等到超时）。③ **静默窗量的是「最后一次改动距今」，不是「我已经看了多久」**——`SETTLE_SECONDS` 240 秒对 24 个 `WATCH_FILES` 共享真源取 mtime 最大值，另加集合快照对比与 15s 复查；`REQUIRED_SOURCES` 里少一个文件直接算缺席（打印「共享真源缺席（有人正在重构）」）而不是跳过——渲染器被删掉的那一分钟里开渲，出来的就是《李尔王》那种片子。④ **封层三方对账**——兜底渲染器、第 14 道门、水波门必须还都点名 `lib/book_cover.py` 的那几个函数（`cover_frame_sequence`/`_cover_motion`、`zoom_at`、`per_frame_cover_masks`），`lib/book-cover.json` 必须能 parse；解析失败打印「有人正在写它」并继续等，因为这三家读同一份 JSON，趁其中一家改到一半开渲就出一段谁也溯不了源的片子。**旁路落在盘上不落在对话里**：`HF_SETTLE_BYPASS` 只有带满 `BYPASS_MIN_REASON_CHARS` 8 个字符以上的理由才放行，理由会被打印进本期日志；理由太短**不是否决**，只是照原样继续等（写成否决会让「打字太累」的人直接绕过整个判据）。等到 `SETTLE_MAX_WAIT` 21600s 判红并说「本期不渲、不进门禁……要么给 HF_SETTLE_BYPASS 写一条真理由」。`HF_SOURCE_ONLY=1` 只是测试缝合（函数定义之后、批循环之前 return），渲染入口仍然只有 `bash scripts/render-hook-batch.sh <书名>` 这一条。**排障读法**：日志里 `[settle]` 那几行会逐轮写明是「有他期渲染在跑／真源缺席／封层没落齐／刚被改写过／最后改动距今 Ns」中的哪一种，✅ 那行还会打出静默秒数与缓存目录；看到长时间等待不要改阈值，先看是哪一类，另一期在渲就等它，别人在重构共享层就等他落完。**回归** `scripts/tests/test-render-serialization.py`（六组 59 条，在 `npm run check` 里，文件缺失即红、少点名任一退路即红）`source` 生产脚本再真的调那五个函数，并且因为判据读的是**环境**（进程表、mtime），测试自己控制这两个输入：PATH 里塞一个 cat `$ZQ_PGREP_TABLE` 的 `pgrep` 桩、夹具 mtime 统一打到一小时前（`stamp_quiet`）——只在别的会话恰好空闲时才绿的回归会被下一个人当噪音删掉。互斥那条用 READY 屏障＋BEGIN/END 区间重叠当证人：同一把锁的两个竞争者**必须**看不到重叠、两把不同锁的**必须**看到重叠（`pairs == 1`），且放行那头还要打印出「锁被占」，否则「两个都成功」可能只是启动运气。两条被记过的形状（`/private/tmp/npm-cache`、`ps -o args=`）各自灌回自己的谓词自检。这条回归第一次跑满就炸出驱动第 307 行的真缺陷：`（$owner），$RENDER_LOCK_DIR`——紧跟全角括号与逗号的裸 `$变量`（`set -u` 下 bash 3.2 把多字节首字节读进变量名，规则见 `AGENTS.md` 的 Validation 末段），位置正好在**接管陈旧锁**那一行，`set -u` 会在报告接管的那句话上把整批渲染带走；现已写成 `${owner}）`/`${RENDER_LOCK_DIR}`，并用 `os.replace` 原子落盘（此刻可能正有 `bash` 在读这份文件）。

  交付前必须量化验收，抽一帧肉眼看「像不像水」不算过——最坏的失败方式是只加声音不加画面，此时时长、字幕、响度、音画对齐全部照常通过，成片看起来完全正常。跑 `python3 scripts/check-water-ripple.py "<书名>-final.mp4"`，它证三件事：① 水声确实在混音里——与 `water.mp3` 做 FFT 归一化互相关（爱玛 NCC 0.916，起点偏离设计点 +0.15 帧）；② 屏上确有一圈外扩的波——逐帧差按半径分环取能量，环质心必须随帧号单调外移（≥45px 且 Spearman ρ ≥0.6）；爱玛实测外移 162px、ρ=1.00，而「只加音效没有画面」的负对照只有 5px、ρ=0.06，两者相差 60 倍，肉眼不可见的抖动骗不过去；③ 声与画的起点相差 ≤1.5 帧。兜底渲染器在候选 `shutil.move` 进 `renders/` **之前**自动跑这道门禁，不通过就不覆盖已交付成片。`npm run check` 再静态盯四条：`WATER_OFFSET` 全仓只在 lib 定义一次、渲染器 import 并调用了 `ripple()`/`water_u`、`adelay` 不是写死的秒数、门禁调用位于激活之前（挪到 `move` 之后即判红，因为那时不合格成片已经落盘）。
- 时间轴 ASR 必须与最终旁白同源：优先对 `body-voiceover-story.mp3` 识别与静音检测；`--skip-leading` 需 token 感知，被跳过首段若是「书名+首句」合并段则回退不跳。书名行即第 1 行脚本行的长文案（如《奥德赛》）用 `--skip-leading 0` 让书名行作对齐锚点。
- 最终成片和纯画面预览都必须直接嵌入对话预览；示例格式：`![最终视频](/absolute/path/to/video.mp4)`。

## 文案规则

- 第一句必须直接抓住观众，不先介绍书，也不铺垫“这本书适合谁”。
- 开头与封面钩子按「5 问」标准设计，写完逐条自检，命中少于 3 条必须重写（标准全文见下节「钩子 5 问标准」）。
- 使用短句、口语化表达和具体生活场景，让情绪先成立，再自然带出书和作者。
- 书籍是情绪和信任的支点，不要写成书评、剧情梗概或主题讲解。
- 画面以氛围感优先，不必逐句解释文案；如果贴合文案会削弱画面，就保留意境。
- 结尾留下余味，不做 CTA，不写购物车、下单、推荐语。

避免：

- “你是不是”式营销开头。
- “不是……而是……”这类重复的 AI 论证句。
- 机械排比和口号化总结。
- “这本书告诉我们”这类生硬讲解。
- 高高在上的劝导语气。

## 钩子 5 问标准

开头 3 秒、封面钩子、文案标题三处必须同一主题，先过这 5 问再出稿。逐条自检，命中越少越要重写：

1. 这和我有关吗？（用「你」或「我」直接关联）
2. 这会不会让我少吃亏？（利益／损失规避）
3. 这是不是和我原来想的不一样？（认知反差）
4. 这个问题我是不是也遇到过？（痛点共鸣）
5. 我是不是想知道后面的答案？（好奇心缺口／悬念）

多平台钩子可共用，但语气分开：抖音＝强钩子／爽感／评论区互动；视频号＝价值感／靠谱／转发驱动。

默认结构是「金句前置 + 代价落差」：把全片核心金句提到 `script-body.csv` 第 1 行正文，紧跟一句制造时间落差。收尾回扣同一句金句，把开头的功能句转成余味，形成首尾闭环。

封面钩子要单独适配静态阅读。封面只有看没有听，金句是**答案**，单独印在封面上等于泄底，优先选问句式或代价式（例：开头金句是「先有用，才配被留下。」，封面用「这句话我花了一辈子才学会」）。`scripts/make_episode_cover.py` 的 `COVER_HOOK` 上限 22 字，超了脚本直接拒绝——40px 单行放不下，先数好字数再出稿。

钩子必须落进 `episodes/<书名>/brief.json`（字段 `cover_hook` / `cover_tag` / `hook_design`），不要只靠渲染时命令行传参：历史期全靠 `COVER_HOOK=` 临时传，下一次渲染就丢，口径无人可查。

## 视频结构

一期成片由三段顺序拼接而成，缺一不可：

```
片头钩子（本期专属） → 固定开场白（模板） → 正文（本期专属）
   script-hook.csv              模板媒体            script-body.csv
   钩子配音.mp3        intro-voiceover-story.mp3   正文配音.mp3
   Pexels 氛围图                                        Pexels 氛围图
```

| 段 | 文案真源 | 配音 | 画面 | 说明 |
|---|---|---|---|---|
| 片头钩子 | `script-hook.csv` | `钩子配音.mp3` | **Pexels 氛围图** | 本期专属，按钩子 5 问标准写；不是模板媒体。段尾 `hook_fade_out_seconds` 0.4s 淡出到黑，接住片头的全黑起幅 |
| 固定开场白 | 无（模板媒体） | `assets/template-audio/intro-voiceover-story.mp3` | 片头模板视觉 | 共享资产，不逐期改；2026-10-05 用户裁决按 2026-10-03 那版**原样**交付（含黑场起幅与书单→结果页那一拍砸黑），抗闪屏的改动只许落在钩子这一路 |
| 正文 | `script-body.csv` | `正文配音.mp3` | **Pexels 氛围图** | 本期专属 |

**片头钩子段和正文段都要铺 Pexels 氛围图。** 钩子段不是纯黑底或纯模板画面——它有本期专属配音和专属文案，铺上本期氛围图才能和正文在视觉上连续；只有中间的固定开场白沿用模板的黑屏玻璃碎片视觉。钩子段的图按钩子文案逐句选，和正文共用同一套调色口径（同一批 `grade-atmosphere-images.py` 一起跑），切镜不得跳色。

**钩子段不压常驻书名层。** `《书名》` 和它下面的作者行只属于正文段：钩子说的是「还没报名字的那句话」，书名一压在顶上，前 5 秒就变成一张书目卡片，而把书名交给观众这件事本来是固定开场白的结果页要做的。实现上 `scripts/create-episode-preview.mjs` 只用一个开关管这件事（`showBookMark`：钩子调用点传 `false`，正文默认 `true`），两条渲染路径都从这里继承，所以不要在单期的钩子组合里手画一层标题。钩子段屏幕上唯一的字就是钩子文案本身。**但开关不是验收**：成片拼的是 `tmp/preview-<slug>/hook/renders/hook.mp4` 这个渲好的文件，改了生成器却没重渲钩子，旧像素照样上片——《恶意》2026-10-01 首版就是这样带着书名层跑完 6.77 秒钩子，而前七道门全绿（它们看字幕轨、看背景、看水波，没有一道看顶部书名带）。第八道门 `scripts/check-hook-no-bookmark.py` 只看成片像素：拿正文段真实书名层几何（`<tmp>/title.png` 的 alpha）当模板，量「字形亮/字缝暗」的反差，钩子窗 >0.20 判红，正文窗 <0.40 也判红（正文看不见书名层说明模板没对上，那是空转的绿灯）。另记一条操作坑：`node scripts/create-episode-preview.mjs` 会清空 `tmp/preview-<slug>/{hook,intro}/renders/`，重生成 composition 之后必须把钩子和片头两段都重渲一遍，否则兜底渲染器会报「缺少 HyperFrames 片头渲染结果」。**钩子集同样要逐张按原始尺寸复核穿帮**：《涅朵奇卡》2026-10-01 正文集那排雪夜里的现代汽车发现并换掉了，钩子集第二张（雪夜路灯）漏检，成片复核时才看到左侧停着一辆厢式车——只有 2.8 秒也照样是穿帮，换成了冬夜里一扇亮着灯的窗（Pexels #34863775）。

`script-hook.csv` 的文案是钩子的真源，`script-body.csv` 是正文的真源，两份都要写进 `episodes/<书名>/` 落盘，不要只在渲染时临时传。`script-body.csv` 第 1 行是书名，正文口播从第 2 行起念；钩子文案不要重复正文开头已经念过的内容（否则片头和正文首句撞车）。历史上只有一份 `script-body.csv` 的期，两段文案都放那一份即可。

模板段（固定开场白）的裁切点是 `INTRO_TRIM_SECONDS`，两条渲染路径（`render-episode-final.mjs` 与 `render_scene_map_template_fallback.py`）默认都是 **3.0s**。这个数字取的是画面而不是口播：共享片头 4.25s 里，结果页（桥接图 + 书名/作者）2.38s 才出现，之后 page-bg 用 1.87s 从 scale 1 缓推到 1.035；裁在 `assets/template-audio/intro-voiceover.mp3` 的 1.83s 会把切点落在候选书单滚动中段，正文首帧就成了「列表页硬跳定格图」的闪屏接缝。口播只有 1.83s，多出的约 1.17s 是结果页定格的静拍，不是缺音。裁 3.0s 时定格倍率约 1.0087，正文首帧必须用同一倍率起幅（fallback 里由 `BRIDGE_ZOOM` 从同一个 `INTRO_TRIM` 推出，不手写）。水波声画同窗落在 `offsetSeconds=0.32` / `durationSeconds=1.06`（`scripts/lib/water-ripple.json`，Python 侧读 `scripts/lib/water_ripple.py`、Node 侧读 `scripts/lib/water-ripple.mjs`），秒数只在这一处定义。钩子段接在模板段之前，齿轮音效与水波按钩子时长整体右移，由 `render-episode-final.mjs` 的偏移量统一换算，不各自手写秒数。钩子配音比模板段长时，超出部分落在正文段开头，按正文处理，不要压缩模板段。

## 封面

- 出图口只有 `scripts/make_episode_cover.py`（渲染脚本调用它，不许内嵌第二份封面代码）；重出封面不用重渲成片：`EPISODE=<书名> python3 scripts/make_episode_cover.py`。
- 底图是本期 `images-body/result-bridge.png` 铺满 1080x1920 + UnsharpMask 补边；书名/作者/钩子整块垂直居中（偏差 >90px 报错），书名**优先单行**（尺寸阶梯见下一条）、钩子 60~72px，不描边，靠柔和投影 + 居中暗色垫底带分离（2026-10-01 用户验收「字体放大、放到中间、不描边」）。
- 字体走 `scripts/lib/title-font.json` 同源解析（2026-10-07 起封面与书名层、正片字幕同族；`COVER_FONT`/`COVER_FONT_INDEX` 已删，不许环境变量第二真源）。
- **书名的排版优先级：单行 > 大字（2026-10-07 用户裁决「调整封面图中的书籍信息排版，书名不要有换行的现象」）。** 阶梯的第一支是「单行能装下就单行」，装不下才折行，判据是 `ONE_LINE_MIN`（100px）而不是旧阶梯的 `TITLE_MIN`（132px）：从 `TITLE_MAX` 168px 往下找单行装得下的最大字号，≥100px 就交单行；连 100px 都装不进，才回到「折成装得下的最少行数」。旧写法先问「132px 下能不能折成 n 行」再回头把每行长回 168px，所以 9 个字的《阿特拉斯耸耸肩》（132px 单行需 1188px > 安全宽度 950px）被折成「《阿特拉斯 / 耸耸肩》」——书名号被劈开、书名从中间断开，而每一行都还是 168px。
  **必须理解的算术：字大和不折行是同一个代价，不是两个可以同时要的参数。** 1080px 画布、88% 安全宽度 950px 下，`字号 × 字数 ≈ 墨宽`，所以 9 字书名只能长到 104px，168px 只能靠折行换来。本期因此从 168px×2 行变成 104px×1 行（信息流缩略图里约 42px → 约 26px）。
  **裁决是「优先单行」，绝不是「一律不折」。**（**这一条连同上面那条只到 2026-10-07 为止**——用户 10-08 用绝对措辞再来一次，折行那一支已经删除，见下一条；今天读到「对这 11 期继续折行才是执行裁决」就去折行，会被第 4 条判红「书名折了行」直接判红；而「给那 13 期写 `cover_title`」也已经是被 10-09 否掉的旧解，见下面第三条。）全库 136 期实测：单行 ≥132px 90 期、112–131px 13 期、100–111px 22 期（合计 125 期单行），剩下 11 期单行需要 62–94px（一个无政府主义者的意外死亡 62、一个叫欧维的男人决定去死 66、一个陌生女人的来信 / 禅与摩托车维修艺术 / 被伤害与侮辱的人们 86、伊加利亚的女儿们 等 94），这一档正是 2026-10-01 用户否掉《恶意》封面时说的「字体模糊不清晰」——对这 11 期**继续折行才是执行裁决**，把它们压成单行就是把被否的观感重新装回去。`ONE_LINE_MIN` 因此是 100 而不是 60：100px 是「不折行」与「不糊」的交点，再往下就是拿一个缺陷换另一个缺陷。相比旧阶梯被这次裁决改变的共 35 期。
- **2026-10-08：「优先单行」被用户第二天的绝对措辞覆盖成「一律单行」——折行那一支是删掉了，不是降级。** 原话是「修改视频封面图中的书名排版，不要有换行，并沉淀这个规则」，约束的是**封面图上那行字**，所以执行形态也跟着变：`wrap_title_lines()` 现在只在**不低于 `TITLE_LEGIBLE_MIN` 96px** 的前提下找单行最大字号，返回的就是那一行；上面那条 `ONE_LINE_MIN`（100px，「低于它就回到折行阶梯」）已退役，`scripts/tests/test-cover-one-line-title.py` 的第⑤组会在 `make_episode_cover.py` 里重新出现 `ONE_LINE_MIN`、或画图那段重新去调折行阶梯时直接判红。正式书名在 96px 下仍装不进单行的，脚本**报错并指名 `cover_title`**：在 `episodes/<书名>/brief.json` 写一个只给封面用的短书名。它只影响封面 PNG——片内常驻的《书名》＋作者层、固定开场白的滚动书单、全部字幕仍走 `display_title`。这是唯一出路，因为另外两条让红线闭嘴的办法各自把用户已经否掉的观感装回来：折行＝10-08 否掉的「换行」，缩到 96px 以下＝10-01《恶意》否掉的「字体模糊不清晰」。取用只有一个入口 `resolve_cover_title()`，`check-cover-wrapping.py` 调的是同一个函数而不是自己再推一遍——回归量 `display_title` 而封面画 `cover_title`，测的就是另一个程序。判红现在有四条：「书名折了行」（任何多行结果）、`wrap_title_lines()` 报错、任何一行超出 `SAFE_W` 950px、以及全库层面的「N 期正式书名单行够不到 96px 却没有任何一期写 cover_title」；防空转的两头改成「单行 0 期＝那一支被删」与「老阶梯会折、现在走单行的期数 0＝这条裁决没落地任何东西」，`old_ladder()` 仍逐字回放被撤的阶梯，所以「新写法产出一行」是断言而不是运气。（当时实测 152 期：单行 139 期、够不到 96px 的 13 期、`cover_title` 已写 0 期，`npm run check` 因此保持红——**这一句连同「该写 cover_title 的 13 期」那条全库红都在下一条里作废**：10-09 用户给这 13 期的出路是缩小字号，不是改名，也不是红灯。）另有一条给改判据的人：`check.mjs` 把这条判红的**原话**钉成测试文件必须点名的 token，10-08 15:56 措辞从「单行装得下却折了行」改成「书名折了行」时门禁与测试同步改了、那枚 pin 没跟上，而它被上面那条 fail-fast 压了一整天才露头——改措辞必须连 pin 一起改。
- **2026-10-09：那 13 期不改名、也不折行，而是缩小字号——「根据合适排版进行缩小字号」。** 上面那条把「单行 ≥96px」与「正式书名不许改」判成互斥，给出路 `cover_title`；用户就同一件事的第三次回答否掉的正是那个出路：**封面印的必须是正式书名，装不下就把字号缩到装得下为止**。于是阶梯的下限从 `TITLE_LEGIBLE_MIN` 挪到新的 **`TITLE_ABSOLUTE_MIN` 60px**，`wrap_title_lines()` 变成「从 168px 往下找单行装得下的最大字号，一直找到 60px」。为什么是 60：它等于 `HOOK_MIN`，也就是封面钩子行自己的最小字号——书名再小就不许比钩子还小，那是层级倒了；`check-cover-wrapping.py` 现在既判「字号掉到绝对下限以下」，也判「阶梯交回的下限不是 `TITLE_ABSOLUTE_MIN`」（把 96 写回那个返回值，等于把缩字号那一支偷偷关回去：超长书名会重新报错而不是照出，然后 13 期一起翻红而根因藏在阶梯里）。**96px 没有被删掉，它从拒绝线变成留痕线**：这是 2026-10-01 用户否掉《恶意》封面「字体模糊不清晰」那一版的实测字号，全库 152 期里 13 期（60~92px）落在它下面，照出，但阶梯必须附一条「书名低于清晰下限」的 note、画图段把它打成 `[warn]`、回归把「低于 96 却没有 note」判红——把警告删了就是让这条裁决静默消失，而把 96 调到和 60 同值让日志闭嘴是同一个动作的另一半，所以 `check.mjs` 钉的是这两个**值本身**（`COVER_TITLE_LEGIBLE_MIN", "96"` / `COVER_TITLE_ABSOLUTE_MIN", "60"`），并且每条钉子先证明自己能被被撤的形状推开。`cover_title` 与唯一入口 `resolve_cover_title()` 都还在，但合法范围窄成「连 60px 都装不进」——现目录最长 15 个字符正好落在 60px，所以 0 期需要它；给本来能缩字号装下的期写短名会直接判红（「改名不是出路」）。2026-10-09 实测 152 期：单行 152 / 折行 0（其中 49 期是老阶梯会折、现在走单行的），低于清晰下限 13 期且全部留痕，需要 `cover_title` 0 期，判红 0。重出封面只是出一张 PNG：`EPISODE=<书名> python3 scripts/make_episode_cover.py`，**不需要重渲成片**。存量已按这条走完（10-09 15:2x）：判据不是「图上字号多大」而是「用现在的阶梯重画一遍，像素变不变」——`tmp/cover-backlog-probe-1009.py` 把每期重画进 `COVER_OUT` 再与盘上那份比 sha256，因为阶梯只能有出图口那一处定义，从图上反推字号就是第二个真源。第一轮 同 40／变 104／缺 1／报错 7，旧图整批备份进 `tmp/cover-backup-1009/` 后就地重出 105 张（含唯一能补的缺图期《少年维特的烦恼》），复跑 同 145／变 0／缺 0／报错 7。两个数别混着报：**真的还折着＝27 期**（`tmp/wrapped-cover-census-1009.py`：PNG 早于 10-07 07:02 且 `old_ladder()` 回放确实折 ≥2 行），**重画会变＝104 期**（多出的 77 期只是三次裁决挪过字号档，不是版式违规）。7 期报错的是名利场／太阳照常升起／爱的艺术／父与子／诺桑觉寺／都柏林人／野棕榈——目录里连 `images*` 和 `result-bridge.png` 都没有，也没有成片，「缺少封面底图」是正确判决，它们的封面跟着自己的出图与渲染那一步来（《太阳照常升起》是并行会话在建期，别碰）。那 104 期里 48 期 brief 没有 `cover_hook`，且都不在 `data/封面钩子-历史存量.json`（那 20 期当年只在命令行传过 `COVER_HOOK=`，已由 `scripts/record-legacy-cover-hooks.py` 认账写进 `cover_hook_legacy`），所以这一批重出没抹掉任何钩子行；若用户指出某期旧图本来有钩子，去备份目录读那行字、写进本期 `brief.json` 的 `cover_hook` 再重出，**不要再在命令行临时传**——那正是 20 期存量的来历。
- **折行本身的规则只在对照回放里活着**（2026-10-08 起出图口不再折行，`_wrap_title()` 只被 `check-cover-wrapping.py::old_ladder()` 拿去逐字回放被撤的阶梯，用来证明「一律单行」不是空断言）：唯一入口 `wrap_title_lines()`（回归脚本调同一份函数，全 152 期判红 0 才算过）；禁则与偏好层留着是给未来任何多行文字（钩子行、后续新载体）用的——断言 GB/T 15834 硬禁则（点号/间隔号/后半括号不领行），偏好层五级「clean＋不孤字 > 词边界＋不孤字 > clean > 不孤字 > ok」，让位半径 ±1；带 `·`／`：`／`，` 的书名在两半都装得下时必须折在标点**之后**（《三体1·地球往事》2026-10-02 折成「三体1·地球 / 往事」就是软的虚词偏好越过了硬的标点锚点）。孤字（末行剩 1 字＋后书名号）是最差的折法（《乞力马扎罗的雪》旧版「《乞力马扎罗的 / 雪》」）；虚词领行只是偏好违例，为防孤字/保词完整性可以让位。**画图那段只许调 `wrap_title_lines()` 一次、不许直接调 `_wrap_title()`**——那是本仓库反复要禁的第二真源形状。

- 同一个脚本还踩过两条**顺序 / 作用域**的坑（2026-10-03 第四批，10 期里只跑完 1 期就整批停住）：① 取图、调色、补压之后必须**先** `write-prompts-csv.py --apply` 再跑溯源门禁——钩子段的 prompts.csv 溯源行只有这个脚本会写，缺这一步脚本过不了自己带的门禁，而它以前一直靠每批手工补；② 每期那块必须是**子 shell 括号** `( … )` 而不是花括号组 `{ … }`：块里每条失败路径写的都是 `exit 1`，花括号组的 `exit` 结束的是整个脚本，外层 `st=$?` 那句「一期失败、继续下一期」从来没生效过。两条都由 `npm run check` 静态钉住（只认调用行，不认注释里提到的脚本名，否则文档会把断言自己判红）。
- `create-body-timings-precise.mjs --verify` 点名必须跟着**发红的那一维**走：行首超阈值就列行首最差的几行，行尾超就列行尾最差的几行。《女儿红》2026-10-03 的红是「行尾最大 3.95s」，而日志下面印的是六行的行首差（0.47–1.15s，全部合法）——读日志的人会去查完全无关的六行。同一期按这条修完，真凶行 100 一眼可见，再走 `retime-asr-segments.py --rows 100`（修 ASR，不动行），行尾最大从 3.95s 掉到 0.96s。
- `script-body.csv` 每一行保持一个完整朗读单元；渲染器优先按逗号、句号、问号等标点分句（仅用于断句，标点本身一律不上屏），每个分句控制在约 12 个汉字以内，过长分句再在内部均衡换行，不能为了排版改动字幕真源。

- 如果用户没有指定 BGM，就从可用曲目中随机选择一首。只有在确认拥有再发布权时，才可以把音乐、音效和口播文件提交进仓库。

## 替换策略

新方案先在 `tmp/` 下生成并验证。验证通过后，再覆盖当前 episode 的活动文件，并删除被替换的旧媒体。Git 只保留已追踪文本的历史；媒体历史默认不保留。A/B 对比文件只能临时存在，并且需要用户明确同意。

## 版权边界

不要把参考视频转录、长篇图书摘录、书评全文、热门划线汇总、下载的社交媒体视频、用户录音、音乐或账号数据写入 Git 追踪文件。本 SOP 只保留独立表述的视频制作方法。
