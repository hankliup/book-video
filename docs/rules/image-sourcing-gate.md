Only after script approval, source the background stills from Pexels (see Visual And Audio Rules): search portrait photos per narrative beat with `scripts/fetch-pexels-images.mjs` (the body set lands in `episodes/<书名>/images-body/`, the hook set in `images-hook/`, selected with `IMAGES_SUBDIR`; `scripts/lib/episode_paths.py` is the single resolver for the `images-body` / legacy `images` name and every consumer imports it, so never re-add a hard-coded `"images"`), record every adopted pick with `PROVENANCE_OUT=<episode>/pexels-fetch-log.jsonl` so the photo id and photographer are written down by the fetch itself rather than remembered, lock the adopted picks by photo id in `data/<书名>_pexels_ids.json` (`segment: "hook" | "body"` disambiguates the two sets, which share `atmosphere-N` basenames), then grade the whole set once per segment (`IMAGES_SUBDIR=… scripts/grade-atmosphere-images.py` followed by `IMAGES_SUBDIR=… scripts/fix-bright-regions.py`; re-run with `--restore` first, because grading is in-place and stacks). Map every row of the segment script to a layer in `episodes/<书名>/scene-map.json` (`{"index","name","order_start","order_end","theme"}`, the static `result-bridge` is layer 0, contiguous coverage of rows 1..max_order), and record each adopted photo's id, photographer, URL, crop and grade in `prompts.csv` with `filename` carrying the real directory prefix (`images-body/…`, `images-hook/…`) so the gate can match a hook row and a body row with the same basename. Declare `"image_pipeline": "pexels-1024"` in `brief.json`, then run `python3 scripts/check-image-provenance.py "<书名>"`; that gate is red when a shipped image has no Pexels provenance, when a layer points at a missing file, when a still is smaller than the 720x960 canvas (the render would upscale it), or when grading was skipped. The gate is red in the **other** direction too — a photo id the manifest locks but no file on disk lands. That check only warned until 2026-10-03: renaming 《海鸥》's `images-hook/atmosphere-16.png` out of the way still printed `背景图溯源门禁：全部通过`, and a hook segment is two beats, so losing one is losing half the hook. A **third** direction is the one that actually shipped a wrong frame: the manifest wants Pexels #A, the disk holds Pexels #B under the same basename, the file exists, is the right size and is graded — so neither direction can see it, because both only ask "is there a file for this id". `fetch-pexels-by-id.py` used to skip any name that already existed; that skip is the entry point. 《偏跟山过不去》 2026-10-03 re-locked a hook beat, the fetcher printed `完成 1/1` while writing nothing, the re-render faithfully put the *old* photograph back on screen, and eight gates stayed green. Identity is now carried by a written marker rather than inferred: every successful fetch records into `images-hook/_provenance.json` / `images-body/_provenance.json` (per filename: `photo_id`, the `_raw/` bytes' sha256, the shipped file's sha256 at fetch time, the source URL it actually pulled), `check-image-provenance.py` reds a marker whose id differs from the manifest («换图没真的落盘»), a name missing from an existing marker, a missing `_raw/`, and `_raw` bytes that drifted under the marker — the last one matters because `grade-atmosphere-images.py --restore` copies `_raw/` straight back over the shipped still, so a stale `_raw` silently resurrects the discarded photo. `lock-pexels-candidates.py` writes `replaces_photo_id` when a re-lock changes the photo, so the fetcher prints 覆盖重取 instead of 跳过. The fetcher no longer treats "file exists" as success at all: without a marker it says it cannot prove the file is that photo, and with a mismatching marker it re-fetches. `scripts/verify-pexels-fetch.py` closes the final gap by re-downloading each still from the recorded `image_url` (never a guessed extension), cropping it with the same `scripts/lib/pexels_crop.py` the fetcher imports, and comparing it to `_raw/` — it is an **opt-in** delivery gate (`check-episode-delivery.py --verify-photos`) because it needs the network, and it reports 未能证明 rather than 不符 when it cannot get the rendition it asked for. **The rendition is now part of the record, not an assumption:** the CDN's `w=1600` and `w=1280` are two *renderings of the same master*, and `crop_3x4()` LANCZOS-resizes each of them to 1024x1365, so their pixels differ — `fetch-pexels-by-id.py`'s width ladder lands on 1280 whenever curl 18 (transfer closed) breaks a 1600 request, and that was invisible to the verifier, which always asked 1600. 《猎人笔记》 2026-10-06 `atmosphere-5` (Pexels #32176786) was fetched at 1280, replayed at 1600, and reddened as 不符 (mean 5.0, peak 71) while the identical replay at 1280 measured **mean 0.000 / peak 0 / overshoot 0.000%** (and at 1024: 10.80 / 136). A false red of that shape sends a person to replace a photograph that has nothing wrong with it, and the cost is a whole body set re-fetched, re-graded, re-rendered. So `certify()` writes `source_width` — the **actual pixel width of the source that landed**, not the rung requested — into `_provenance.json`, and `verify-pexels-fetch.py`'s `replay_width()` resolves the rung in three steps (marker's `source_width` → the `_original/<name>.png` width for pre-2026-10-06 markers → default 1600), refuses to compare at all when the resolved width is below `TARGET_W` (a crop from there is an upscale, so it proves nothing), and reports 未能证明 — never 不符 — when the CDN returns a width other than the one recorded. `scripts/tests/test-replay-width.py` runs the real `main()` against a stubbed CDN and asserts all three directions (same rung + same photo green, same rung + different photo red 「不符」, same photo + different rendition red 「未能证明」 and its output must not contain 不符), plus that the rendition-vs-rung gap itself is >3× `MEAN_TOL` so the test cannot go vacuous; `npm run check` runs it and statically guards that the test still names `replay_width`, `source_width`, `fetch_bytes` and both script filenames. Do not substitute a perceptual hash for the marker chain: measured on this very set, the *same* photograph raw-vs-graded scores dHash distance up to 31 while two *different* photographs score as low as 12, so once grading is in-place a hash cannot prove "this file is that photo" — the checkable chain is manifest id → `_provenance.json` → `_raw` sha256 → graded still → delivered frame (`scripts/check-hook-frame-match.py`), and `npm run check` statically guards that the marker is written *and* read, that one `crop_3x4()` serves both fetcher and verifier, and that the exists-skip still goes through `certified_existing()`. A marker is demanded only in an image directory that already carries one, so the delivered legacy episodes stay out of the blast radius instead of turning this into a hundred-episode dig. Cross-*episode* duplicates used to stay outside every gate — the same photograph could sit in one episode's body and another's hook and nothing in the repo could see it, because every check only ever opened one episode. That stopped being acceptable the moment the 113-episode hook backfill made it the normal case (two hook beats × a hundred-plus episodes drawing on one Pexels library): 11 hook stills across 10 episodes replayed a photograph the viewer had already seen in another episode's body, and all eight gates stayed green. The judgement now has a single source, `scripts/lib/pexels_index.py` (`photo_id → [(episode, segment, filename)]`, built once per process from every `episodes/*/prompts.csv` and every `data/*_pexels_ids.json`), and **three** consumers share it: `scripts/pexels_candidates.py --exclude-used` drops already-shipped ids at search time so a batch never has to re-review them, `scripts/lock-pexels-candidates.py` and `scripts/lock-pexels-selection.py` refuse a hook pick the repo has already shown (a deliberate callback needs `--allow-used-elsewhere` plus a `reason` in the picks file), and `check-image-provenance.py` reds a locked hook still that any other episode has shipped — naming the offending layers. **A body pick is checked in the other direction only: `lock-pexels-candidates.py` refuses a photograph any other episode has already shipped *as a hook* (`if x[1] == "hook"`), because the red line lives on the hook side and the intrusion comes from the body — 《猎人笔记》 2026-10-06 locked Pexels #13438765 into body `atmosphere-4`, twelve gates green for that episode, and the `npm run check` sweep reddened 《女儿红》, a film delivered on 10-03 whose hook had already shown that photograph. Body-to-body repeats stay tolerated (#34938048 sits in ten episodes' bodies) — blacklisting them empties the pool batch after batch and a passing overfield carries no "where is this" expectation.** `npm run check` statically guards that all three are still wired to the lib and that `foreign_uses()` is defined nowhere else. **`--exclude-used` cannot see a photograph a human rejected**, because a rejected pick was never shipped — so the same defect photo came back every single batch: the six frames of one 大理稻田 family snapshot (Pexels `alt` = the garbage tags "animals, Beautiful scenery, beautiful woman", so *any* atmosphere query recalls them) surfaced in 15 candidate batches during the fourth hook batch on 2026-10-03, and a Chinese village corridor with a row of readable notice boards (#39854273) in 18. Manual rejection that lives only in a chat session is not pipeline state. `data/pexels-rejected.json` is now that state, read through one entry point, `scripts/lib/pexels_reject.py`: `pexels_candidates.py` drops those ids by default (`--ignore-rejected` only to re-audit a rejection), and **both** lock scripts refuse to lock one — the exemption is a photo already present in that episode's own manifest, because re-locking a segment must not be bricked by a list that grew afterwards, and withdrawing a shipped still is a re-pick + re-render, never a list edit. Write entries with `scripts/reject-pexels-photo.py`, which refuses a reason that is not one of the three *globally* disqualifying defects (a face, readable signage, a staged lifestyle/prop shot) and refuses an id that already shipped. Do **not** add a photograph that is merely wrong for one episode: a 江南 white-walled courtyard is a defect for a 西北 village story and a correct still for another, and blacklisting per-episode mismatches just shrinks the pool batch after batch. `npm run check` guards the four wirings plus that every recorded reason is one of those three classes and no recorded id has ever shipped. A related failure the same batch exposed: a transient proxy `503 Tunnel connection failed` used to end a query for good, so three of twenty hook beats came back with 3 candidates instead of 6, a reviewer then wrote 「无可用，需重检索」, and a whole episode got re-picked because of a network hiccup — `pexels_candidates.py` now retries those (4 s/8 s backoff) and exits **3** naming the queries that never completed, which means *the pool is narrower than designed*, not *Pexels has no such photograph*. A hook-only re-lock is merge-preserving in both the manifest writer and `write-prompts-csv.py`: 14–23 body provenance rows must survive it (《秋园》 2026-10-02 lost them to an overwrite write). Note that the index is only as complete as the manifests and CSVs it reads — an episode directory moved out of `episodes/` leaves its `data/*_pexels_ids.json` behind and keeps contributing to the dedup set, which is what you want; a delivered episode with *neither* file is invisible, so never delete provenance to tidy up. The gate measures size, luminance and traceability — it cannot see an anachronism, so before locking picks, open every shipped still at full size (never a thumbnail contact sheet) and look for objects that could not exist in the story's period or place: a lit green EXIT sign over a staircase, a row of snow-covered cars on the street where a character walks out without shoes, signage, antennas, plastic chairs. Both defects were shipped and caught only on review in 《涅朵奇卡：一个女人的一生》 2026-10-01; a 13 s EXIT sign and a 48 s car-lined street pass every quantitative gate unchanged, so replace the pick, re-grade the whole set, and update the manifest, `prompts.csv` and the layer `theme` together. When the anachronism is only *at one edge* of a photograph whose light, colour temperature and emptiness are right, do not discard the pick — give the manifest entry a `"crop_box": [x0,y0,x1,y1]` (fractional window applied to the source before the 3:4 centre crop), and `scripts/fetch-pexels-by-id.py` will cut the object out of frame while `write-prompts-csv.py` prints the real crop method instead of claiming a centre crop. 《达洛维夫人》 2026-10-02: 13 of 18 shipped stills carried a defect (a bus shelter, a delivery scooter, Japanese shop signage, double-yellow lines, two tourists in modern dress beside an arcade), and the one image that could not be re-searched — every Bond Street candidate had the same problem — was kept and fixed with `crop_box [0,0,0.8,1]`, which is why re-searching a beat that has no clean photograph left is the wrong move. A third class is not modern at all and no keyword filter can catch it: a *staged prop still life* whose every object is old but belongs to another culture, or a photograph that illustrates the spoken line literally instead of carrying its mood. 《异乡人》 2026-10-02 shipped the 守灵 beat as a horned cattle skull behind an elephant-relief silver cigar ashtray — nothing anachronistic, its Pexels `alt` named no defect, and it passed the size/luminance/traceability gate unchanged — but it is not a 1940s Algiers retirement-home room, and it draws 「他想点一根烟」 as a picture-book ashtray. Reject that pick for an empty room with one chair; judge it on place and on atmosphere, not only on "could this object exist".
