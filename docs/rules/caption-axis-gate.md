# 字幕轴：ASR token 时间戳与覆盖率

3. When body voiceover is supplied, process it with the `story` preset, use ASR only for timing, and keep `script-body.csv` as subtitle truth. Build the caption axis from ASR **token timestamps**, in this order: `node scripts/asr-segmented.mjs "<book>" episodes/<book>/audio/body-voiceover-story.mp3` → `python3 scripts/asr-to-simplified.py episodes/<book>/audio/asr/body.json` → `node scripts/create-body-timings-precise.mjs "<book>"` → `python3 scripts/snap-body-timings-vad.py "<book>" --apply` → `python3 scripts/audit-caption-axis.py "<book>" --apply`. A pause-tiling axis (`create-body-timings.mjs`) is a degradation, not the default: it tiles captions end-to-start so the shape looks perfect (last `end` ÷ duration ≈ 0.99, zero gaps) while every row is attached to the wrong sentence — 《茶馆》 2026-09-28 shipped 14–16 s late at rows 38-45 and every gate stayed green. The audit pass removes the five residual defects that a token axis still has (late start, mid-speech blank, unreadable window, tail dragged into a pause, and a tail so thin it dilutes the row's own voiced share below the gate's 45 % — rule C2, which trims only to the row's last audible burst) and leaves caption *starts* alone unless rules D/E fire, because at −50 dB a token onset and an energy onset differ by 0.03 s median while a threshold-driven head move swallows weak initial consonants. Those head rules must run **twice** — once before the C/C2 tail pass and once again after it, immediately before the monotonic guard — because rule D decides whether a row can move onto its own onset by looking at the *previous row's `end` at that moment*, and the previous row's tail is not reclaimed until C/C2 run, so a single head pass always loses the silence that C2 has just freed. Rule D's witness is the −50 dB silence runs, which answer only "is there a pause", so a sentence read without an internal pause merges into **one continuous voiced block** and `onset_of` hands D the onset of the *block*, not of the row's first word; when that block onset sits at or before the previous row's `end`, `on > prev_end + 0.10` is never true, and a head a full 0.77 s late is invisible both to the fixer and to the audit's own residual count (《李尔王》 2026-10-04 rows 15/27 「她说，父王，」: the last −50 dB silence ends at 28.56 while the block runs to 34.4, row 14 ends at 28.60, so only gate 7's per-row coverage saw it). Rule **D2** (`late-start-own`) is the fallback: it re-reads the witness the delivery gate itself uses (`lib/caption_speech.audible_windows` → `own_spans`) and moves a head **earlier only**, onto that row's own audible onset, and only when the previous row has released the space and the window stays above `min_window` — moving a head later stays forbidden because it swallows weak initial consonants. Control-measured: on 李尔王 D2 fires on exactly those two rows and drives gate 7 to 0 reds, while dry-running the audit over eight delivered axes (异乡人/三体1·地球往事/偏跟山过不去/秋园/茶馆/追忆似水年华/等待戈多/人间失格) reports **zero** `late-start-own` changes, so the rule touches only axes already fighting gate 7; `npm run check` statically guards that `fix_heads` still consults `own_spans` under that note kind. Measured on 《达洛维夫人》 2026-10-02 with the same snap output as input: one pass leaves `行首落后 2 行` residual (row 41 parks 0.39 s, row 88 0.46 s after their own onsets) and gate 6 exits non-zero; the second pass drives the residual to 0 with gate 7 unchanged at 0 reds. Do not "fix" the thin-tail reds by adding a third trimmer to the coverage pass — `snap-body-timings-vad.py` deliberately holds its 0.60 s lead-out and its 0.90 s readability floor, and the audit's rule C2 owns density with the audit's own 0.55 s read floor; two hands trimming tails to two different floors is the divergence that re-opens row after row.
   The coverage pass goes **before** the audit pass, never after: `snap-body-timings-vad.py` forces each caption window to cover the window in which its own words are audible and holds a row up to 0.60 s past them, while the audit's rule C trims exactly that kind of tail hold — audit-first would be re-widened, snap-first leaves the audit free to trim tails and fill blanks without uncovering a row (verified on 《恶女的告白》 2026-09-28: after `audit-caption-axis.py --apply` changed 31 rows, `check-caption-speech-align.py` still reported 0 reds).
   The coverage pass exists because a token axis is only as good as Whisper's predicted timestamps: without DTW every token `t_dtw` is `-1` and in-window times are linearly squashed, so a row can be attributed to the right sentence and still be 1–3 s off it (《恶女的告白》 2026-09-28: |Δstart| median 0.12 s but max 1.33 s on the corrected axis, 3.04 s on the shipped one). `scripts/snap-body-timings-vad.py` derives, per row, the window in which *that row's own characters* are audible — ASR character order to pin the row to tokens, waveform energy bursts to pin the pinned head/tail to something you can hear — then makes each caption window cover it, yields to the next row, holds at most 0.60 s past its own speech, and never drops below the 0.90 s readable window. Row heads may only move into a real silence gap; the tail of the previous row's lead-out is the first thing reclaimed when a row needs more time. `scripts/lib/caption_speech.py` is the single source of that "audible window" so the fixer and the gate cannot diverge; `check-caption-speech-align.py` judges the shipped `caption-track.json`, not `body-timings.json`, because the renderer still stretches short rows by characters ÷ speaking rate. That stretch must stay **capped by the density of the window it creates**: `render_scene_map_template_fallback.py` measures the energy bursts inside the row's axis window and refuses any extension that pushes the *whole resulting window* below `CAP_VOICED_MIN` (0.50, five points above the gate's 0.45), because the 0.90 s readability floor plus a 0.3 s single-word row is 33 % voiced and no axis can be walked out of that (《恶意》 2026-10-01 row 1 「恶意」: axis 0.36–0.95 scored 51 %, the hard floor dragged it to 0.36–1.26 and gate 7 went red — `CAP_MIN_KEEP=0.6` was the old per-episode hand patch, the cap is now automatic). The cap must **not** be phrased as "yield when the tail genuinely carries speech": the burst right after a row's end is usually the *next* row's first syllable, so that test passes on a tail that buys this row nothing. 《达洛维夫人》 2026-10-02 row 130 「她想，」: axis 235.36–235.91 scored 51 %, the next row opened at 236.20, the old test saw 0.06 s of energy in the 0.35 s it wanted to borrow and stretched the row to 236.15 — 0.79 s window, 0.28 s of its own speech, 35 %, gate 7 red again *after* the axis itself had gone green. The same window also parks the next row's first character under the previous caption, which is the mirrored defect the coverage pass forbids. Sharing that lib is not sufficient — the fixer and the gate must also **listen to the same audio file**: `audit-caption-axis.py --voice` defaults to the re-encoded `audio/body-voiceover-story.mp3` while `snap-body-timings-vad.py`, `check-caption-speech-align.py` and the renderer all read `audio/body-voiceover.mp3`, and because the burst threshold is adaptive to each file's own noise floor, two copies of one identical take disagree (《恶意》 2026-10-01: the same audible tail ends at 19.34 s on the story copy and 19.25 s on the shipped one, so row 11 scored 52.9 % voiced to the fixer and 44.9 % to the 45 % gate — a red the axis could not be walked out of). The audit's rule C2 measures bursts from `audio/<segment>-voiceover.mp3` and treats `--voice` only as the −50 dB silencedetect source.
   Sharing the audio file is not enough — the two sides must also share the **definition** of window density. `lib/caption_speech.voiced_share()` is now that single definition for gate T2 and for C2 and for rule B's borrow cap: silence *inside* the row's own audible window and shorter than `MAX_OWN_PAUSE` (1.5 s) is that row's own reading rhythm and is not 空放, while silence *outside* it is the defect. 《奥兰多》 2026-10-02 row 42 「吹着真相，真相，真相。」 spreads 8 syllables over 3.6 s with 1.05 s and 1.21 s dramatic beats, so its raw density is 35 % and no axis move can reach 45 % — trimming the tail to 95.87 still scores 37 %, and T1 forbids uncovering the last 「真相」 by shortening the head; a raw-density gate there is demanding the narrator not pause, so it was the measure that was wrong, not the row. A weak-anchored row (ASR homophone → no own window) falls back to raw density, and the gate keeps an absolute `--min-raw` 20 % floor so a caption parked on pure silence stays red under either measure.
   **富余停留 — the padding rule A demands — is the second silence that is not 空放.** `voiced_share(..., readable=)` additionally exempts the part of the window that exists only so the viewer can *finish reading*: `lib/caption_speech.reading_need(chars)` — `READ_RATE` 5.2 chars/s with a `READ_FLOOR` 0.55 s, i.e. **the same formula audit rule A uses to call a window unreadable** — and only up to `reading_need` minus the time the row's own words are actually on screen. 《人性的枷锁》 2026-10-04 row 72 「而是：」: 2 characters audible for 0.14 s inside the 0.90 s window the snap floor requires, so 0.67 s of head padding scores 26 % density — red on T2, and unfixable on the axis, because rule A refuses to trim a window it itself declares too short to read. Two rules holding one row in place is a measure defect, not an axis defect. The `MAX_OWN_PAUSE` exemption cannot see it (that silence sits *outside* the row's own window), so this is a second class rather than a widening of the first. Three guardrails, all asserted by `scripts/tests/test-voiced-share-readable.py` (in the `npm run check` loop, with static guards on the four wirings): the exemption needs `readable` **and** a real own window, so a weak-anchored row keeps the old verdict; it never exceeds `reading_need`, so a 2-character row parked 3.0 s is still red at 26 %; and `--min-raw` is untouched, so a caption on pure silence is 0 % burst_share and stays red either way. `--no-read-pad` reproduces the old caliber for any future A/B. Measured old-vs-new over 118 delivered episodes: shipped tracks 143 → 113 red rows (36 caption entries flip, 6 of them still red because their T1 coverage is short — the mirrored defect, which must stay red), axes 141 → 120, and **no row flips in the other direction**.
   The bursts that feed that measure are compared in **integer frames**, never in seconds. `speech_bursts()` used to convert each frame index to seconds before testing `MIN_BURST`/`GAP_MERGE`, and `(8260-8245)/100 = 0.14999999999999858 < 0.15` deleted a real 0.15 s utterance: 《一个陌生女人的来信》 2026-10-04 row 28 「不断等待。」 lost 0.38 s of its own audible window and scored 31 % density on the one row the axis had nowhere to move. Compare in frames, convert only on return, and keep `scripts/tests/test-speech-bursts.py` running in the check loop — it reproduces the float underflow on the same synthetic waveform so the assertion cannot go vacuous. That fix was silently reverted by a concurrent edit 35 minutes after its test landed, which is why the regression, not just the code comment, is the deliverable.
   **A blank is a defect only while words are audible.** Rule B used to ask the −50 dB silencedetect alone: 68.10–68.73 in 《奥兰多》 is only 17 % silence there (a breath, not a word), so B borrowed the previous row's tail all the way to the next onset, and gate T2 — listening to bursts, which see no voice in that 0.6 s — scored the tail 40 % and rule C2 trimmed it back, giving the same fixer-fills-while-the-gempties deadlock as the two-audio-file bug, on a row that could not be walked out of it. B's trigger and `measure()`'s blank count now also require `burst_share(gap) ≥ speech_share` (0.30) on the gate's own audio, so a real pause between two sentences may carry no caption at all and C2's trim survives; when B does borrow, it walks the borrow back until that row's `voiced_share` stays at or above the T2 floor, never below the row's own readability floor. Dry-running the new rules over healthy delivered axes (《德米安》《克林索尔的最后夏天》) reports `changes: 0`, so the tightening only touches axes that were already fighting the gate.
   **A red axis must be named before the render, not after it.** 2026-10-08 fifth batch: 《夜莺与玫瑰》《呐喊》《动物农场》 each spent ~10 min rendering three segments, then gate 7 (逐行盖住自身语音) reddened — the defect was the **axis**, not the pixels: those three `audio/body-timings.json` had never gone through the snap/audit passes (audit dry-run reported `changes 34`, `before.late 2→0`; snap moved heads by up to 0.98 s), and nothing in the render chain ever asked the axis a question before rendering. 《夜莺与玫瑰》 was one layer more convoluted: the axis was repaired at 11:13 while the film had been rendered at 11:06 from the pre-repair axis, so `caption-track.json` no longer matched it (row 63 axis starts 261.35 / track 262.05) — gate 7 judges the *track*, so its red was correct, and the only remedy was "re-render with this axis", ten minutes already spent. `python3 scripts/check-axis-before-render.py "<book>"` is that ten-second decision: it re-runs the three axis witnesses already in this section (`create-body-timings-precise.mjs --verify`, `check-caption-speech-align.py` in axis mode, `audit-caption-axis.py --json`) and reads **their own verdict lines** — it restates no threshold, because a fourth place that asks "is the axis right" in different words is exactly the fork this repo keeps paying for. Red → it runs the documented order (`snap --apply` → `audit --apply` ×2, the ×2 being rule D/D2 needing a second pass after C/C2 frees the silence) and re-measures; still red → exit 1 and `scripts/render-hook-batch.sh` skips the episode. `scripts/tests/test-axis-guard.py` runs three arms on a hard-linked fixture copy (`cp -al` for the mp3s and `asr/` only — the axis json and its `.presnap`/`.pre-audit` evidence are real copies, and the test re-hash-checks the donor directory afterwards): a healthy axis exits 0, heads artificially delayed 0.45 s exit 1, and the same dirty fixture goes green through the repair arm. That second arm records a non-vacuity detail worth keeping: a pure head delay leaves the **token witness green** — 0.45 s sits inside its true-median tolerance, since legal snap/audit head moves are that large (《三体1·地球往事》 0.36 s, 《你的夏天还好吗》 0.60 s) — so the red must come from the other two witnesses; if a future run reddens only the first, a threshold moved and this assertion breaks first. A track-vs-axis mismatch is *not* detectable by any gate (the boundary sweep uses the track as its own truth), which is why the guard runs before rendering rather than afterwards.
   When a coverage red points at *one* row whose own words really are audible but whose token window is wrong, the suspect is Whisper's in-segment time squash, not the axis: repair the ASR, not the row. `python3 scripts/retime-asr-segments.py "<book>" --rows <n>` cuts only that segment's window (plus a small pad) out of the body voiceover, re-recognises it at short-clip resolution, and adopts the new token times only when the new text still covers the segment's own characters **and the composite defect score strictly falls — 无声 + 压扁**: characters whose interpolated time lies wholly inside a real silence gap, plus characters the in-segment time squash crams into a `CRAM_WINDOW` (0.5 s) slice holding more than `CRAM_CAP` (8) real words — 3.4× the measured house rate, so a healthy axis never trips it. Silence alone is not enough a judge: in 《一生》 段13 (124.40–137.84 s) the squash packed two dozen characters into the segment's last 0.3 s, which happens to be the *next* sentence's audio, so the silent-character count was 0, the old axis looked untouched, and the shipped track still pinned row 38 「那批公债后来违约，钱一夜之间缩水」 to 137.01–137.26 (14 characters in 0.25 s). The judge has to see both "where there is no sound" and "where nobody could speak that fast". That segment was adopted on the composite (`压扁 29→0`, `无声 1→5`, score 30→5) and **rejected by the old silence-only judge**, which read 1→5 as a regression and printed 保持原时刻 while leaving gate 7 red on row 40's density. Verified again on 《人性的枷锁》 段13 2026-10-04: 无声 9→4, 压扁 0→0, adopted, and gate 7's residual red moved off rows 65-67 onto row 72 — which is how the 富余停留 caliber defect surfaced. It records the decision as a `retime` block on that segment and keeps a `.pre-retime` backup, so `create-body-timings-precise.mjs --verify` stays honest. Then re-run precise → snap → audit in order and re-render. Two repairs are forbidden: re-running whole-file ASR with a smaller segment target to "fix" one row (《追忆似水年华》 2026-09-28: 45/92 rows lost their anchors and became 0.3 s fake tiles), and pushing a row's `end` forward with pause-snapping so the caption sits in the following silence (that is the mirrored defect — it parks the caption in a 0.98 s gap and steals the next row's speech).
