# 字幕：字符流、时间轴与显示

- Body subtitles use `script-body.csv` as text truth and `body-timings.json` when valid. "Valid" means token-derived: the shipped row must sit on the sentence that is actually being spoken, not merely fill the timeline. Three independent witnesses exist — ASR token timestamps (text↔time), `silencedetect` energy boundaries (blank↔speech), and the per-row audible window built from both (`scripts/lib/caption_speech.py`: ASR character order pins a row to tokens, waveform energy bursts pin those token ends to something you can hear) — and **all three** are delivery gates (`create-body-timings-precise.mjs --verify`, `audit-caption-axis.py --json`, `check-caption-speech-align.py --track`); shape-only checks (last-`end` coverage ratio, zero inter-row gaps, RMS envelope, loudness, the caption boundary sweep) are blind to row attribution and stayed green on an axis that was 16 s off. A row's caption window must *cover its own audible window*; ending a caption while its words are still being read out is a defect even when the next caption appears on time, and holding a caption through silence the row never spoke is the same defect mirrored. Judge the rendered `caption-track.json`, never only `body-timings.json`, because the renderer lengthens short rows by characters ÷ speaking rate. Missing, stale, or low-confidence timings must trigger a visible Agent-review warning and automatic fallback to speech duration or script hints rather than blocking preview or render, but a fallback axis must be re-derived before delivery, not shipped. Long Chinese lines must wrap within the 720px frame and remain visible. Anchor every caption to absolute `round(t * fps)` frames rather than accumulating per-item rounded durations, which drifts the whole track late in a 3–4 minute film. Pinning a row to tokens assumes the two sides share an alphabet, and Whisper breaks that assumption on spoken numbers: it writes 「六十八岁」 as the token `68` (《嫌疑人X的献身》 2026-10-04 row 120, `68`@213.77–214.23), so **no** character of the row matches the stream, the row gets no own window, and gate 7 can only read it as 空放 while the axis has nowhere to move — its head can only land on the row's first character, and all three of those characters are swallowed by one digit token. The fix is a **digit fold to Chinese, digit by digit, on both sides in both languages**: `clean()` in `scripts/lib/caption_speech.py` (which every Python fixer and gate reads) and `canonDigits()` in `scripts/create-body-timings-precise.mjs` each map `0-9` and full-width `０-９` to 零一二三四五六七八九 before matching, so a script that writes Arabic digits (`1928`) still meets an ASR `19`/`28` digit-for-digit and only digit-vs-Chinese changes verdict. Digit-by-digit, **not** cardinal: BPE splits a year into `19`/`28`, and reading those as 十九/二十八 dates the row to the wrong sentence, while a stranded 十/百 in the copy is just another unmatched char that `align()` already interpolates between its two real anchors. `npm run check` statically guards the four wirings (both tables identical, both sides folded on both paths). Measured across all 120 delivered axes: 117 verdicts unchanged, weak-anchor counts only fall (this episode 5→3), and 2 episodes gain a *newly visible* late-start red (《白夜行》 row 141, 《追忆似水年华》 row 41 — its caption opens 0.58 s after its own 十五 is already audible), which is the caliber seeing a defect it previously could not measure, not a new defect.
- **The character stream must contain only characters somebody spoke.** whisper.cpp emits a family of **控制 token（control tokens）** — `[_TT_<digits>]` (a predicted timestamp), `[_BEG_]`, `[_EOT_]`, `[_EP_<digits>]`, `[zh]` — and both sides used to filter them with a hand-written regex that was missing the closing bracket: `re.match(r"^\[[_A-Z]+\d*$")` in `asr_char_stream()` and `/^\[[_A-Z]+\d*$/u` in `buildAsrTokens()`. A token starting with `[` therefore matched *nothing* and stayed in the stream — not a drift but a double silent failure, invisible to every gate. Measured over 60 `body.json`: 2636 `[_TT_…]`, 510 `[_BEG_]`, 10 `[_EOT_]`. Two distinct damages: on the Node side these zero-length/boundary pseudo-tokens rewrite `gapOnset`, which is what row heads snap to; on the Python side `clean()` strips the brackets but keeps `_`, letters, and **folds digits**, so `[_TT_628]` contributes the seven phantom characters `_TT_六二八` — and after the digit fold those are the same characters as a number that really was read out, so a row can win a fake anchor whose time is the segment boundary rather than a spoken moment (139 of the 165 per-token start-time regressions in the catalogue belonged to them: 165 → 26). One shape now owns the decision, `CONTROL_TOKEN = ^\s*\[[^\]]*\]\s*$` — "balanced brackets, no bracket inside" rather than a prefix table, because `_TT_` suffixes will keep being added and a prefix table is how the next 「正则漏了 ]」 stays silent. Both sides must carry the same shape and `npm run check` extracts the two pattern texts, asserts they are identical, then **runs** the pattern: it must match all six observed forms (plus whitespace padding) and must not match 他 / x / `[x` / 你好 / `[]x` — a bracket-count check alone would have passed the withdrawn regex, since its `]` sits inside a character class while the pattern still fails to match `[_TT_628]`. `scripts/tests/test-positional-anchor.py` ①② reproduce both directions on real token text, including that the old caliber really did let the ghost digits steal a hit.
- **A row whose words were heard but written wrong is not a row without an anchor.** difflib's matching blocks only cover literal hits, so a homophone mis-hearing leaves a gap: `align()` used to interpolate every gap linearly, which assumes each syllable is equally long — and a homophone is precisely evidence that the syllables exist one by one. When the script side and the ASR side are missing the **same number of characters** between two literal blocks (`gs == ga > 0`), the i-th dangling script character now takes the i-th dangling token's own `from/to` — a **positional anchor** (按位对位) — instead of an interpolation, and it sets `flags[k]` while leaving `matched` literal-only, so the 「ASR 字序命中 X / Y」 log stays comparable with history. Unequal counts (a dropped syllable, a doubled one) never guess: 宁可内插不可编时刻. The pass is decided **per gap, never per character** (measured: 0 gaps across 136 episodes mix positional and interpolated characters), which is also why the "merge positional anchors into the interpolation ladder" line is a provable no-op today (`tmp/probe-ladder-noop.py`: 0 characters differ) — it is kept as the floor for the day someone makes the pass partial, and the overshoot it describes was the first draft's real shape, whose keys started at `b0.a` instead of `b0.a + b0.size` and overwrote the previous literal block's own times. That off-by-one is why the first catalogue A/B printed 「46 行获得锚点」: a contaminated control, not an effect — `test-positional-anchor.py` ⑤ and the static guard on the key base are the two things that keep it from coming back. **The same rule had to be extended to the two gap positions `zip(blocks, blocks[1:])` structurally cannot see** (2026-10-10, 《挪威的森林》's hook): the characters before `blocks[0]` and after `blocks[-1]` fell through to two fallback branches in `align()` that do not interpolate — they **invent** times (编时刻): a leading dangling run is pinned to the first anchor's own `from/to` (one shared time for the whole run), and a trailing one gets `te0 .. te0+0.20` out of thin air. The trailing branch is what blocked that episode: row 2 「一响照旧」 was mis-heard as 「一想招救」 — `gs == ga == 3`, exactly "heard that many syllables, wrote the wrong characters" — but because it is the *last* gap it never entered the pass, so the row was invented to end at 8.18 s while its speech is audible to 8.65 s. `snap-body-timings-vad.py`'s ceiling is then own-speech-end + 0.60 = 8.78 s, and 8.78 ÷ 9.12 = 0.963 < 0.98 → 「时间轴塌陷，拒绝写入」, the whole episode stuck on the axis. 《面纱》 meanwhile carries 0.556 s of trailing silence and scores 0.9927, because its last Whisper token happened to land on the burst end — **0.98 is a proxy, the thing itself is "does the last row cover the last audible moment."** The two edge gaps now use the *identical* condition (`gs == ga > 0`; unequal counts still never guess, and no threshold was added), each counted in its own index space: the leading ASR side runs `0 … first.b`, the trailing runs to `len(asr_concat)`. Writing `first.b + off` aliases the dangling script characters onto the first *matched* block — the same off-by-one that contaminated the earlier probe, whose 「238 段 / 11 行 / 46 行获得锚点」 are withdrawn. The fresh A/B (`tmp/ab-align-tails-1010.py`, 246 segments) is surgical: 52 segments carry a qualifying edge gap, the other 194 are character-for-character identical, 「不该动却动了」 0, 36 segments change a row window, **7 rows gain an anchor / 0 lose one**, no episode's weak count rises, exactly one axis unblocks (《挪威的森林》 hook 0.9627 → 1.0), 0 green→red, 0 errors, and no Δstart is positive (30 rows, median −0.155 s — heads only move earlier, which is what this repo asks). `test-positional-anchor.py` ⑦⑧⑨⑩ pin it both ways, including a 4-vs-3 unequal-count negative control proving the new branches are conditional rather than default-all-anchored, and `check.mjs` now statically requires `pos[off] = off`, the trailing `last.a + last.size + off = last.b + last.size + off` pair, both index-space counters, and those four names in the test — because a branch whose only witness is a comment is a branch the next concurrent edit deletes. **The Node axis builder needs no mirror of this rule, and that is a measured scope rather than an assumption:** `create-body-timings-precise.mjs` has no interpolation branch to fix — its per-row boundaries come from a per-character LCS plus forward/backward *fill*, so a mis-heard tail simply stops at the last literal hit (《挪威的森林》 hook row 2 shipped as `4.64–7.98` for exactly that reason) instead of inventing a `+0.20` end. The two paths differ in **role**, not in definition: the Node file estimates row boundaries, while `align()` is what `audible_windows()` — and therefore snap's ceiling and gate 7 — read for per-character time. Re-running the Node witness on the repaired body axis reports 行首 |Δ| 中位 0.205 s / 最大 1.159 s, 行尾 0.25 / 1.07 s and still ✅, which is the tolerance that keeps that division of labour from being read as drift; if a future change makes the Node side invent tail time, *that* is the fork to close. Measured effect of the pair (control token + positional anchor) over all 136 episodes with a body ASR: **anchor-weak rows 79 → 7**, axis red rows 124 → 128, delivered-track red rows 112 → 111 (26 rows change side, 11 gained / 19 lost). Three delivered films flip green → red — 《乱世佳人》 rows 60/71 open 0.87 s / 0.80 s after their own speech, 《秘密花园》 row 81 0.61 s and row 129 density, 《荆棘鸟》 row 34 density — which is the caliber measuring a misalignment it previously had to abstain on, not a new defect, and the remedy is one re-snap + re-audit + re-render per episode, never a threshold. 《无名的裘德》 rows 103/129 stay red under both calibers: the old one could only say 「窗内语音 10% <45%」, the new one can say the caption opens 0.59 s after 浴 is already audible — naming it is what makes rule D2 and the snap coverage pass able to fix it. Related diagnosability fix in the same gate: T2 now prints **only the criterion actually crossed**, because a row exempted by the reading-pad rule used to read 「窗内语音 100% <45%」 and sent a person to chase a line that was never red.
- Subtitles never display punctuation. `script-body.csv` keeps `，。？！、；：…` only as clause markers that the renderer splits on, and `·` only as a name separator; the policy itself lives in `scripts/lib/subtitle-punctuation.json` (`displayStrip` / `displayBreak` / `displayBreakTo` / `displayKeep`) and **every** renderer that draws captions — including a per-episode `render_<book>_template_fallback.py` — must import `scripts/lib/caption_display.py` instead of hard-coding a set: a hand-copied table that only right-strips each wrapped fragment still paints an interior `、` on screen (《白鲸》 order 53 「庞杂、缓慢」), which passes resolution, duration, caption-alignment, and loudness checks unchanged. After the wrap is settled, strip the clause markers for drawing: **every** break mark (`，、；：。！？…`, the `displayBreak` set) becomes a real line break and every other mark disappears, so a drawn line contains neither punctuation nor a whitespace gap. The earlier mode that swapped an interior pause mark for one full-width space U+3000 was retired on 2026-09-27: 「漂亮[全角空格]聪明[全角空格]有钱」 reads on screen like missing characters, and whether it wrapped at the gap was left to container width, so one line of copy typeset differently on the two render paths. Sentence-final marks are break marks too, otherwise two glued sentences paint as one unreadable run. `·` stays (斯蒂芬·茨威格), and so does the persistent `《书名》` overlay with its author line — those are template identity, not subtitles. Wrapping happens inside the 652px caption container at 56px; one caption holds at most `displayMaxLines` (2) visual lines, and a row that needs more is split into **sequential captions** — never a smaller font, never a joined-with-space line. Run `python3 scripts/check-caption-punctuation.py <episode>/caption-track.json --csv <episode>/script-body.csv --strict` before delivery; it fails on any mark or whitespace gap left on screen and on any caption over the line budget, but only if the track carries the on-screen `display` text — a renderer that emits just the punctuated CSV original turns the gate into "N/N rows have no display field", so emitting `display` (and a copy of the track under `episodes/<book>/`) is part of the rule. Each track entry also carries a `captionStyle` marker (`line-break@<displayBreakVersion>`): `--strict` judges every episode by the new rule, `check-caption-punctuation.py --all` downgrades unmarked historical tracks into a re-render backlog table instead of lighting up every delivered episode at once. `npm run check` enforces the policy shape and the render-path edits statically for non-baselined renderers and additionally runs `check-caption-punctuation.py --all` across every episode. Draft clean from the start; when converting an annotated source such as `文案.md`, run `python3 scripts/strip-subtitle-symbols.py "<book>" --apply` first (symbol-only, verified character by character) and let `validate-script.mjs` reject leftovers.
- Body rows must carry no decorative symbols in the text itself: no `《》`, quotes `“” ‘’ 「」 『』`, em dashes `——`, or parentheses. Write the book title bare, render quoted inner voices as plain statements, turn an em dash into `，`, and add `、` where adjacent quoted words would otherwise collide. Never delete the clause-marking punctuation from `script-body.csv` itself — without it the renderer cannot split clauses or snap them to speech pauses; removing it for display is the renderer's job.
- Keep each script row as one complete spoken unit for ASR alignment. The renderer first breaks at commas, periods, question marks, and similar punctuation only to find clauses; each clause stays within roughly 12 Chinese characters. If one clause is longer, it is balanced across multiple visual lines without changing the source text.
- Keep videos under 60 seconds unless the user explicitly changes the limit.
