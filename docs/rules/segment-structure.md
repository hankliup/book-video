# 三段结构与共用片头

- Every episode is three sequential segments, and all three must be present: hook → fixed intro narration → body. The hook and body are per-episode (`script-hook.csv` + `钩子配音.mp3`, `script-body.csv` + `正文配音.mp3`); the middle is shared template media (`assets/template-audio/intro-voiceover-story.mp3`, 1.83s) that is reused as-is and never regenerated.
- **Both the hook segment and the body segment carry Pexels atmosphere stills.** The hook is not a black or bare-template screen: it has its own copy and its own voiceover, so it takes this episode's atmosphere images and stays visually continuous with the body. Only the fixed-intro middle keeps the template's black glass-shard look. Grade the hook images in the same pass as the body images so cuts never jump in colour. **A hook still must be a photograph this episode's body has not used.** The two segments share `atmosphere-N` basenames and each carries its own provenance row, so size, luminance and traceability all stay green while the hook replays a frame the viewer already saw minutes earlier — 《秋园》 2026-10-02 locked the hook's first beat onto Pexels #34938048, byte-identical to body `atmosphere-3`, and it surfaced only when the candidate was opened at full size. `scripts/check-image-provenance.py` now reds any photo id shared between the two segments (it names both layers), and `scripts/lock-pexels-selection.py` refuses the collision at lock time; pass every already-adopted id to `scripts/pexels_candidates.py --skip` so the search never offers a used photograph back. A deliberate callback is a different device and stays body-only: a scene-map layer with `reuse_of`.
- `data/<书名>_pexels_ids.json` records the episode's whole adopted set, so re-locking one segment replaces **that segment's** entries only — `lock-pexels-selection.py` merges by `segment` instead of rewriting the file, because a hook-only lock overwrote 23 body picks with 2 rows on 2026-10-02 and left `prompts.csv` as the only surviving record of the body set. `scripts/write-prompts-csv.py` is likewise merge-preserving: rows its manifest does not cover stay in the CSV unless the file they name is gone. **Segment ownership is written at lock time, on every entry, and it is what routing reads.** `lock-pexels-candidates.py` stamps `dir` + `segment` unconditionally, `fetch-pexels-by-id.py` routes each entry through `scripts/lib/episode_paths.segment_subdir()` (which resolves a directory-less legacy entry by probing `images-body` → `images` and **never** lets `IMAGES_SUBDIR` route a body still into `images-hook`), and `--segment=hook|body` restricts a run to one segment. That triple exists because `prepare-hook-segment.sh` hands the **whole** manifest to the fetcher with `IMAGES_SUBDIR=images-hook FORCE=1`: on 2026-10-06《猎人笔记》the body entries carried no `dir`, so the resolver's `IMAGES_SUBDIR` override (legitimate for the per-segment grading pass) re-routed all 16 body stills — each was re-downloaded at raw brightness into `images-hook/`, overwriting the two graded hook frames, while the body set lost its in-place grading. Every gate stayed silent: files existed, sizes were right, provenance rows matched, and only the *contents* of the hook frames had changed. `scripts/tests/test-segment-routing.py` (in the `npm run check` loop) asserts all three layers plus the negative control that the old resolver does route to `images-hook`, and `check.mjs` statically requires that test to keep naming `segment_subdir`, `dirs_for`, `ONLY_SEGMENT`, and `--segment=hook` in `prepare-hook-segment.sh`.
- **The persistent `《书名》` + author overlay belongs to the body segment only — the hook segment must not carry it.** The hook is the line before anybody has been named: printing the title over it turns the first 5 seconds into a book catalogue card and spends the reveal that the fixed intro exists to deliver. `scripts/create-episode-preview.mjs` gates this with one flag (`showBookMark`, false for the hook call site, true for the body) so both render paths inherit it; do not reintroduce a hand-drawn title layer in a hook composition. The hook's own copy is the only text on screen there. **The flag is not the check.** The film concatenates `tmp/preview-<slug>/hook/renders/hook.mp4`, so a composition change that was never re-rendered ships the old pixels: 《恶意》 2026-10-01 carried the title over the whole 6.77 s hook with `showBookMark: false` already in the generator and all seven gates green — none of them looks at the top title band. `scripts/check-hook-no-bookmark.py` (gate 8 of `check-episode-delivery.py`) reads the delivered frames and measures the glyph-vs-interstice brightness contrast against the body's real overlay geometry (`<render-tmp>/title.png` alpha): contrast > 0.20 anywhere in the hook window is red, and the body window must show contrast ≥ 0.40 as the positive control, because a gate that cannot see the overlay where it *does* belong is a green that means nothing (measured on 《恶意》: stale hook +0.585, clean hook −0.018…0.000, body +0.84). Note that `node scripts/create-episode-preview.mjs` wipes `tmp/preview-<slug>/{hook,intro}/renders/`, so regenerating compositions must be followed by re-rendering both before the final can be rebuilt.
- Keep both segment scripts on disk under `episodes/<book>/` (`script-hook.csv` and `script-body.csv`), not just on the render command line. `script-body.csv` row 1 is the book title and the body voiceover starts at row 2; the hook copy must not repeat what the body already says first, or the hook collides with the opening line.
- The template segment is trimmed at `INTRO_TRIM_SECONDS` — **3.0s on both render paths** (`render-episode-final.mjs` and `render_scene_map_template_fallback.py`). The trim point follows the picture, not the voiceover: the shared intro is 4.25s and its result page only appears at 2.38s, so cutting at the 1.83s voiceover length would splice the rolling book list straight onto the body's first frame. The template voiceover stays `assets/template-audio/intro-voiceover-story.mp3` (1.83s); the remaining ~1.17s is the silent freeze on the result page. The water ripple is frame-locked by `offsetSeconds` / `durationSeconds` in `scripts/lib/water-ripple.json` (read by `scripts/lib/water_ripple.py` on the Python side and `scripts/lib/water-ripple.mjs` on the Node side). Because the hook precedes the template, the gear SFX and the water shift right by the hook duration — compute that offset in `render-episode-final.mjs` instead of hand-writing seconds anywhere. A hook voiceover longer than the template segment spills into the body segment and is handled as body — never compress the template to fit. **This is an assertion, not a reminder:** the timetable lives in `scripts/lib/intro-template.json` (`scroll_start` / `scroll_end` / `result_page_at` / `trim_seconds` / `voiceover_seconds`), and both `render_scene_map_template_fallback.py` and `check-episode-delivery.py --intro-trim` refuse any trim below `result_page_at`, because the wrapper recomputes the water window, the caption sample times and the hook gate from that same offset and will certify a wrongly-cut film eight greens otherwise. 《恶意》 2026-10-01 shipped at `INTRO_TRIM_SECONDS=1.83` — the voiceover length, not the picture's — so the cut landed mid-rolling-list and the last frame before the body was **another book's cover card** (this episode's list happened to be showing 《百年孤独》); the renderer's seam metric reads MAD 181.94 in the picture region and 185.58 in the title region at that cut, versus 5.32 / 11.53 once trimmed at 3.0s. If a render or a gate run is being re-invoked from memory, re-read this value rather than reusing the shell history line.
- Use the shared template in `templates/shared-video-template/` as the only visual baseline.
