# 正文常驻来源声明

- **The body segment carries one permanent attribution line, verbatim: 「内容为书评与感悟[全角空格]素材来源于网络」** (the two parts are joined by one full-width space U+3000 — `lib/disclaimer.py`'s `display_text()` does the joining, so no side may write it). The copy came from the user and is not ours to rephrase, shorten, or re-punctuate. It is a **body-only, whole-segment** layer: never in the hook and never in the shared intro, exactly like the persistent `《书名》` + author mark — the hook is the line before anybody has been named, and a disclaimer on it is the same 「把揭示提前花掉」 defect. Wording, font size (26px), bottom margin (44px), grey (150,150,150 at α 0.9), gap, shadow, and the 720×960 canvas live in **one** file, `scripts/lib/disclaimer.json`; the two readers are `scripts/lib/disclaimer.py` (`load` / `geometry` / `overlay` / `mask` / `core_mask`) and `scripts/lib/disclaimer.mjs` (`disclaimerCss` / `disclaimerHtml`), and both render paths import them instead of drawing a copy: `render_scene_map_template_fallback.py` composites the lib-rendered `TMP/disclaimer.png` as a single overlay layer on `#root` (so it cannot fade with a scene and is not in the per-frame caption pipe), and `scripts/create-episode-preview.mjs` injects the CSS/HTML behind a `showDisclaimer` flag that is `false` at the hook call site. A hand-copied word, a re-inlined `parts.join("")`, or a second set of coordinates is the fork this whole structure exists to prevent.
- **Where the line may sit is a band calculation, not a layout preference, and it is machine-enforced.** The ink box lands at y 885..924 on the 720×960 canvas — below the caption boundary sweep's sampling window (`BAND = (0, 680, W, 850)` in `scripts/qc-caption-alignment.py`) and below the flicker gate's 取证窗口 (`LUMA_BAND_ROWS = (0, 35)` of a 36×48 probe, i.e. y<700). Both readers of `disclaimer.json` reject at import time any `font_size_px` / `bottom_px` whose ink box intersects those bands, and `npm run check` re-parses the two consumer constants and compares them to the recorded `reserved_bands`, so moving a threshold on one side turns the check red instead of silently re-opening the collision. That matters precisely because the line is a *permanently composited* layer: inside the caption band the sweep scores ink that is not a caption, and inside the luma window a static layer changes the frame-to-frame statistics that criterion ⑥ reads.
- Delivery gate 12 is `scripts/check-disclaimer-overlay.py`, wired into `check-episode-delivery.py` as 常驻声明上屏, and it judges **delivered pixels** — a rule that lives only in a generator would be the same defect class as 《恶意》's stale hook. Two witnesses: (A) the episode's `disclaimer.png` is compared to the lib re-render, then each sampled body frame minus `body-bg.mp4` is reduced to residual ink and IoU-matched against `lib.mask()`, with the implied glyph luma required to stay inside `ink_luma_range` — so the line must be *present as drawn*, not merely as a file on disk; (B) a temporal per-pixel std ratio inside the band, which is what lets the hook window be judged red when it carries a static layer even with no `body-bg.mp4` to subtract (the ratio, not a binary changed-map, because a 0.9-alpha overlay leaks 10% of the background's motion through it). Do not buy a green with white or black type or by sliding the line into the caption band: 字面亮度 reddens both, and the grey is the user's request. Blast radius: an episode whose intermediates predate the layer prints ⚠️ 无从证明 and exits 0 — the 120+ delivered films are not a backlog to re-render for this — but `--require` turns that into a red and must be used for anything newly rendered; the fallback renderer also writes a `body_mp4 + ".disclaimer-sha"` sidecar so a `REUSE_BODY` hit assembled before the layer existed cannot be reused into a delivered final. `scripts/tests/test-disclaimer-overlay.py` (in the `npm run check` loop) asserts it flips both ways on synthetic clips — healthy green, missing layer red, present-for-only-part-of-the-body red, hook-carrying-the-line red, stale wording red, white and black type red, witness-B-only red, legacy ⚠️ — plus that the JSON's numbers are the CSS the generator emits, and `npm run check` statically guards the four wirings that would disarm the gate (the renderer importing and calling `overlay()` and actually compositing `disclaimer_png`, `showDisclaimer: false` surviving on the hook call site, no hard-coded copy in any renderer, and the wrapper still calling gate 12) and `scripts/tests/test-disclaimer-overlay.py` flips it on synthetic clips.
  **2026-10-06 amendment — α, and what the colour sample is taken from:** the lib's fill and shadow are now **α = 1.0** with a hard unblurred shadow (the user's 「水印状态保持固定」 ask: a partial-alpha overlay is a mix with the plate, so it breathes across scenes — see the playbook's 常驻叠层 clause), so the 「α 0.9」 wording in the two paragraphs above describes the 10-05 shape. That change silently blinded the colour criterion on the same day: the implied glyph luma is inverted with the **lib's** α and sampled from `core_mask()`, which selected "alpha ≥ 0.92·a" anywhere in the composited overlay — once the shadow is fully opaque its α equals the glyph's, so the black 3px shadow joined the sample and a deliberately **white** line measured 163 rather than 250, i.e. inside `ink_luma_range` and green (a control that cannot flip is theatre, and this one is documented above as 「white and black type red」). `core_mask()` now samples the glyph-only layer via `overlay(..., draw_shadow=False)`, and the test builds its white/black controls from the lib's *current* α instead of a hard-coded 0.9, because a control drawn at a different α than the one the gate divides by measures the composite, not the type.
