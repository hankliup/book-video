- **Two more strobe causes are in the composition, not the template artwork, and both are the same arithmetic.** Measured on 2026-10-04 while re-rendering the fourth hook batch: after the junction and the page band were fixed, four of the ten films were still red on the gate's 「去了又回」 criterion, and in every case the dip was inside the episode's own footage. **(a) the intro's fade-up is a runway, not a transition.** `xfade` is a convex combination, so dissolving the hook's last frame under an incoming layer that is itself climbing from pure black gives `hook_tail × (1−t/D)` — down 8.7–16.4 grey levels and back up, in all ten films, at the same timestamp. The 2026-10-04 answer was to *skip* that part of the incoming clip: hold the hook's tail frame for `opening_runway_seconds` (measured by `scripts/lib/intro_runway.py`) and dissolve only onto the intro's plateau. **The user withdrew that on 2026-10-05, so the same arithmetic now gets a hook-side answer: `hook_fade_out_seconds` 0.4 fades the hook's own tail to black, so the intro's ~0.47s flight-from-black lands on a picture that is already dark and there is no composite at all — one convex combination removed by never overlapping the two clips, not by holding a frame over them. The intro segment stays `trim=0:INTRO_TRIM`, uncut and uncomposited, and the length is legal only because 0.4 ≥ 判据④'s 0.35s time-scale (a shorter fade is 「去了又回」 again); `scripts/tests/test-hook-seam-fade.py` pins all of that, including that both render paths read the number from the lib and actually draw `fade=t=out`. ****(b) a two-layer CSS cross-dissolve over a black canvas is not a cross-dissolve.** `scripts/create-episode-preview.mjs` faded the incoming scene in *and* the outgoing scene out with the same easing at the same time, which composites to `f·top + (1−f)²·bottom` — the midpoint is short by `f(1−f)·bottom`, i.e. 25% of the bottom layer at mid-dissolve. Fixing it by picking darker photographs would be dimming-to-pass — the fix is to **not** fade the outgoing layer at all (keep it at `opacity: 1` and let the incoming one cover it), which makes the result the same convex combination `xfade` produces in the body. **That half alone turns the dipping dissolve into a one-frame hard cut, and a hard cut is redder than the dip was.** `.photo` is `position:absolute; z-index:1`, while a `.scene` with no `z-index` only creates a stacking context *while its opacity is below 1*: an outgoing scene that never fades stays `opacity:1`, so its `.photo` escapes into the root's positive-z group and covers the whole incoming scene (a z-index:0 group member) until its opacity hits exactly 1 — at which point it stops being a stacking context and its own photo wins by DOM order. Measured on 《丧钟为谁而鸣》's hook after only that first half: the 0.72 s window 3.73–4.45 s did not move at all (flat 60.7) and frame 4.47 stepped to 39.9 — 判据③ red at 20.8 > 17.7. The old shape *looked* like a dissolve precisely because the outgoing layer was fading, which demoted it into a stacking context: **the dip and the hard cut are two faces of the same bug.** So `.scene` carries an explicit `z-index: 1` — every scene is always a stacking context, paints as one unit at the same level, ties break by DOM order, the incoming layer is genuinely on top, and only then does `opacity:1` on the outgoing layer produce the convex combination. Which layer of the evidence chain the mask is allowed to trust is itself a rule, ordered hard→soft: ① `--cover-witness PATH` (the caller hands over the render-time witness), ② `tmp/<书名>_tpl/book-cover.json` inferred from the episode name, ③ `--exclude-cover` (the renderer's own declaration that it just composited the layer), ④ `episodes/<书名>/book-cover.jpg` on disk — printed as 「兜底线索，不是事实」, because material on disk does not mean the film carries it; nothing at all → whole-frame judgment, 宁可多判不可漏判. The asymmetry that justifies rung ④ is measured, not assumed: 漏排 is an −80px false red while 多排 costs only ~35px of drift (108.3 → 73.6 on a cover-free film, still green by a margin below `DRIFT_PX`), so a witness that over-excludes is safe and a silent abstain is not. The witness must record `motion` (the fallback renderer writes `"motion": _cover_motion(cfg)` into `book-cover.json`) — `lib`'s motion changed twice inside one day, so the footprint has to come from the copy that drew *those* pixels; when a historical witness carries a motion the lib now refuses (`motion()` rejects `zoom_to ≠ 1.0`), the gate prints 「未通过 lib 校验」, falls back to the lib's current motion and keeps going rather than crashing, and the printed 面积 proves which caliber ran. Two things that must stay true: an episode with no cover layer is **bitwise** the shipped calculation (the no-mask branch is literally `bincount(diff)/counts`, asserted against an independently recomputed copy over 61 frame diffs), and excluding the card must never make a film that has no water look like it has some — a card-only film stays red after exclusion (`motion` 0.0001 < `MIN_MOTION`), while the *unexcluded* card-only film fakes two of the three criteria (逐帧差 0.6645, ρ 0.993) and is stopped only by `DRIFT_PX`, which is why that number is pinned by value in `check.mjs` with a decoy self-test (a pin that ignores the number is theatre). `--legacy-static-box` exists only as the A/B control wall and is forbidden at both production call sites (`check-episode-delivery.py` gate 3 and the fallback renderer), each of which passes `--cover-witness`; `scripts/tests/test-water-cover-exclusion.py` runs in the `npm run check` loop and is itself name-guarded on 「未检出封面层 / 旁证 motion / 找不到封面图 / 未通过 lib 校验 / `--legacy-static-box` / `visible_denominator`」 so the four retreat paths cannot be deleted for convenience.
