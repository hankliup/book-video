# 片头闪屏的裁决与归因


  What survives is one device: `hook_fade_out_seconds` 0.4 in `scripts/lib/intro-template.json` — the single source, read by **both** render paths, drawn as `fade=t=out:st=` so the hook's last frame sinks to black before the intro's own 0.13s black flight begins. The junction stays a hard cut and criterion ① still judges the seam pair: delete that fade and a mean-60 hook still slams into 0.0 at |Δ|>40 and goes red. That is asserted twice — `scripts/tests/test-hook-seam-fade.py` (static: lib is the only length source, both render paths draw it, plus the gate's own `flickers()` fed a synthetic sequence proving a fade-to-black is not a 「去了又回」 while the same position without the fade is) and `R8` in `scripts/tests/test-flicker-rules.py` (same film, fade removed → 闸刀 red).
- **The ruling binds delivered pixels, not only source files, so gate 11 `scripts/check-intro-is-original.py` asks whether the intro *inside the shipped mp4* is the restored one.** A source-level rollback says nothing about a film rendered before it: the ruling itself removed the only criteria that looked at the intro window (②~⑥ are now exempt there), and `composition-digest.py` fingerprints the *generator*, which genuinely is current — so a pre-rollback film prints ten ✅ while carrying the rejected look. Three witnesses, each derived from the template's own truth rather than a hand-written number: **W1 接缝黑场** needs frames below `BLACK_MAX` in `[hook_dur − hook_fade − 0.15, hook_dur + 0.30)` (the hook's fade into the template's own flight from black; the retired `opening_runway_seconds` + `junction_dissolve_seconds` pair could never reach black there); **W2 底图电平** needs every `held_levels()` plateau of `[hook_dur + scroll_start, hook_dur + result_page_at − 0.30)` to sit within `LEVEL_TOL` 12 of a level measured off `media/_raw/pages/scroll-*.jpg` through the flicker gate's *own* 36x48 probe (`raw_page_levels()`; measured: healthy films ≤5.1, the graded 155–185 band ≥38); **W3 砸黑一拍** needs black frames in `[hook_dur + result_page_at − 0.50, hook_dur + result_page_at + 0.10)`, i.e. `.template-blackout` still exists in the pixels. W2 compares a **set** of levels, not a frame-position-by-frame-position diff, because which cover is on screen at which second is itself an editorial detail that has moved since (the 13:13 page reorder), and measured 2026-10-05 two post-rollback films differ by MAD 96 inside the rolling window on timing and page order alone — a cross-film pixel diff would reddise healthy films while a graded band cannot hide from a level-set comparison. `--as <书名>` judges a copy that lives outside `episodes/`; that exists for the controls, because a gate that can only ever see films inside its own directory cannot demonstrate that it can see a wrong one.
  Controls are both ways and reproducible: `scripts/tests/test-intro-is-original.py` renders six openings with ffmpeg (healthy = `_raw` plates + seam fade + blackout → green; the 10-04 shape → red on all three; the 155~185 band / 压暗 / blackout-removed / no-seam-black → red on **only** W2 / W2 / W3 / W1) plus two shapes that must print ⚠️ 无从证明, and the 压暗 case is the one that keeps the ruling honest — push the plates to ~40 and W2 reddens, so buying a green with a dimmer is a red, not a pass. Read one limitation of W2 before trusting it alone: on a *real* graded film the six plates collapse into a single held level, so `held_levels()` recognises < `MIN_LEVELS` platforms and W2 prints 「⚠️ 只认出 1 个平台：不计入判决」 — it abstains instead of reddening. The synthetic 155~185 fixture keeps ≥3 platforms (its five levels are deliberately spread 167–173), so the test proves W2 *can* see the band while the shipped-film evidence for retiring it comes from W3, which named every one of the six films rendered on 10-06 under the withdrawn look, and from `check.mjs`'s byte-identity guard on the seven source plates, which is what stops a flattened set from ever being rendered again. Its segments are encoded `-color_range pc` because the default limited range encodes `0x00` as y=16, which is above `BLACK_MAX` 8: a test whose "black" reads 16 measures the encoder rather than the witness. Real films after the 10-06 re-rollback (census `tmp/intro-original-census-1006.txt`, re-measure of the 10-05 one at `tmp/intro-original-census/all-1005.txt` = 48 green / 6 red / 73 无从证明): **43 green / 11 red / 73 无从证明** — the 73 are two-segment films with no `script-hook.csv`, where the intro *is* the first shot and there is no seam to ask about. The 11 reds split by cause: 5 pre-rollback films still carrying the held-tail/dissolve seam (嫌疑人X的献身 10-04 14:27, 乡下人的悲歌 10-04 14:35, 白夜行 10-04 14:39, 群魔 10-05 10:36, 格兰特船长的儿女 10-05 10:58 — all red on W1) and 6 rendered on 10-06 between 14:10 and 15:40 while the withdrawn re-grade was live (解忧杂货店 14:10, 少年Pi的奇幻漂流 14:36, 李尔王 15:15, 人间草木 15:21, 雪国 15:25, 秘密花园 15:40 — all red on W3, W2 abstaining as described above; 《李尔王》 had been green on the 10-05 census and was re-rendered *into* the withdrawn look today). - **豁免的是范围，不是阈值 — and the exempt range is printed, never hidden.** `judged_segments()` in `scripts/check-luminance-flicker.py` splits the opening window into judged parts `[floor_start, hook_dur − hook_fade_out_seconds)` (the hook's own footage) and `[hook_dur + trim_seconds, +1.0s)` (the body's first second), and an exempt part covering the hook's tail fade plus the shared intro window `[hook_dur, hook_dur + trim_seconds)`. Criteria ①~⑥ keep their exact shapes, thresholds, allowances and reference (each film's own body) — the same brightness shape placed in the hook still goes red, which is what `R2`/`R7` in `scripts/tests/test-flicker-rules.py` pin by moving one identical blink between the two positions and requiring the verdict to flip while the judged frame count stays byte-identical. Every run prints the exempt window's own numbers (峰值 / 最暗 / 来回处数 / MAD 峰值 / 越带 / 「按同一套判据本会翻 N 项红」) so the cost of the ruling sits on the page instead of inside a threshold: re-rendered 《等待戈多》 reads 203 judged frames with opening peak 3.8, darkest 52.3 and all six criteria green, while its 103-frame exempt window reports peak 93.4, darkest 0.0 and five 「去了又回」 — five criteria it would have flipped. When the film's three-segment structure cannot be resolved (no `episodes/<书名>/`, no `script-hook.csv`, a synthetic clip) the gate **does not exempt** and judges the whole window, because without `hook_dur` there is no line where the intro starts: 宁可多判不可漏判.
- **判据⑥「漏底」is the sixth cause, and it exists because ①~⑤ read frame-to-frame deltas while a bad dissolve has no big delta.** `scripts/create-episode-preview.mjs` used to fade the incoming scene in *and* the outgoing scene out with the same easing, which composites to `f·B + (1−f)²·A` on a black canvas — the midpoint lands below both plateaus, `depth = B²/(4A)` for the double fade (and the same algebra for the two-layer case), while a convex combination never leaves the band between its two sides. Measured on a delivered 《李尔王》 hook: single-frame peak 4.1, 「去了又回」 0 处, MAD under allowance — ①~⑤ all green — with a five-frame dip of 5.6 levels between two plateaus. The criterion therefore compares each held level pair's excursion band and reds at `EXCURSION_MAX = 0`, with the depth floor `max(3, 0.08 × 带宽)`: the *ratio* term is what stops the cheapest wrong fix, because depth and bandwidth both scale with brightness, so dimming the pair (case C in the regression: A=76/B=38) keeps `depth/带宽` unchanged and stays red, and dimming far enough (case D: A=38/B=19) just hands the verdict to ②眨眼. Evidence is `scripts/tests/test-dissolve-undershoot.py`, which renders two real dissolves with ffmpeg and runs the gate's own `main()`: convex green / double-fade red / dimmed-still-red with the same ratio / caption positive control — and it pins the **取证窗口** (rows 0~34, i.e. above the caption line) because a caption is an independently-added ink layer, not a convex combination of two photographs; the whole-frame caliber redded two healthy episodes (《丧钟为谁而鸣》 3.2 级上冲, 《一个叫欧维的男人决定去死》 3.9 级下探) and the fix was to move the window, never to raise `UNDERSHOOT_TOL`. Levels are matched by `held_levels()` on *both* conditions (整段极差 ≤3 级 **and** ≥15 帧) — per-frame tolerance alone registers a slow dissolve trough as a third level, splits one reversal into two monotone legs, and blinds the criterion (《李尔王》 2026-10-05, measured 0 处 on a real 5-frame dip).
- **A red that the attribution tool cannot own is the same defect as a green that meant nothing, so ⑥ had to be wired into the attribution — by calling the gate, never by re-typing it.** The gate reports six criteria but `scripts/check-flicker-attribution.py` measured only ①~⑤, so on 2026-10-05 27 of the 32 backlog films printed a verdict line (「❌ 漏底：⑥最深下探 5.6 级」) followed by 「闪屏归因：无红段」 — the one tool whose whole job is to answer *who fixes this* was blind to the criterion that names almost the entire backlog, and the human reading it has no action. The attribution now decodes through the gate's own `frame_curves()` (one pass, and it is the pass that also yields the caption-free 取证窗口) and calls `dissolve_excursions()`/`held_levels()` with the gate's own defaults, so there is no second floor, no second tolerance, no second band — `npm run check` statically requires the test file to keep naming `judged_segments`, `dissolve_excursions` and `frame_curves`, because a revert to a hand-copied threshold is how ⑥ went blind in the first place. ⑥'s **scope** is the gate's `judged_segments()` itself, not a list re-written here: it can only redden 钩子自身 and 片头→正文切点, and the identical shape inside the shared intro window prints its 越带 count and depth with 「不在门禁判决范围，只报告」 and stays green — 豁免的是范围，不是阈值, asserted numerically (the test compares the tool's ⑥ range against `judged_segments()` frame-for-frame) and asserted on real pixels (《李尔王》 5.6 级@3.80s / 5 帧, 《人间失格》 13.1@4.07 / 12 帧, 《白夜行》 7.0@4.23 / 10 帧 all match the gate exactly, while the re-rendered 《等待戈多》 reads 越带 0 处). The *owner* follows from the algebra rather than from a hard-coded claim: a convex combination cannot leave the band between its two held levels, so an excursion can only be a two-layer reverse fade — in the hook band that is the shape `create-episode-preview.mjs` used to emit (it now fades only the incoming layer), so ⑥ there reads 共享预览生成器 / 重渲即消, and at the intro→body cut it is 装配层 / 重渲即消. That is the same conclusion the ledger reaches from the other direction, and it holds: every one of the 10 films re-rendered after the rollback is ⑥-green. When ⑥ is the *only* red in a band the tool suppresses the band's ordinary 「归属：」 line and prints 「漏底归属：」 alone — two owners for one defect sends a person to re-pick photographs that were never the problem. `scripts/tests/test-flicker-attribution.py` (26 assertions, in the `npm run check` loop) pins all of it both ways, including the cross-band negative: the same dip synthesized into the intro's 书单→结果页 beat must print its number and flip nothing, and a film carrying *two* defects in one band (照片差太大 + 淡出漏底) must print two separate owner lines.
- **A gate can only certify pixels it can trace, so every batch render now writes a ledger and reads it back.** One `hyperframes render` takes tens of seconds, and a concurrent session re-running `create-episode-preview.mjs` can rewrite the same composition directory in the middle of it — the mp4 then holds half-old, half-new pixels, and all ten gates go green because each of them asks "is this frame right" while none asks "which composition produced this file". That is exactly how 《李尔王》 shipped its fourth 「还是闪」 report: `index.html` changed at 10:10:42, the render finished at 10:10:58, and the delivered film carried the pre-`z-index` `.scene` shape. `scripts/composition-digest.py` closes it: `render_segment()` in `scripts/render-hook-batch.sh` digests the project directory (every regular file except `renders/`, `node_modules/` and third-party `gsap.min.js`) **before and after** each render, and a mismatch deletes the mp4 and retries rather than feeding the gate; on success it records 组成指纹 + 成片 sha256 + 生成器指纹 (`create-episode-preview.mjs`, `lib/intro-template.json`, the fallback renderer) into `renders/<段>.provenance.json`, mirrored to `episodes/<书名>/renders/` because the next preview generation `rm -rf`s the preview `renders/` and a ledger that disappears with the pixels it certifies can never be read. After the ten gates, `composition-digest.py verify <书名>` reads that ledger and reds when the generator has changed since the recorded render or the mp4's bytes no longer match — the one mechanical form of "this film carries a previous generation's shape, re-render it, nothing else fixes it". An episode with no ledger prints ⚠️ 无从证明 and stays out of the verdict (the ledger started 2026-10-05 12:48; reddening a hundred delivered episodes for their birth date would bury the real list). `scripts/tests/test-composition-digest.py` asserts both directions: touching `renders/hook.mp4` must **not** move the digest (a product may not testify for its own source), one byte of `index.html` must move it, and `verify` must flip green→red on a doctored generator or a drifted mp4.
